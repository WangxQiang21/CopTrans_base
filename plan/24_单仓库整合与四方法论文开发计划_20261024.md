# 单仓库与四种方法简明计划

## 目标

最后只维护一个项目目录，里面有四种可比较的方法：三种论文方法和一种强化学习方法。三个论文名称还没定，暂时叫方法 A、B、C。

## 计划，只做四件事

1. **留一个项目。** 以当前 `expv3` 为主项目。已把运行所需的 `fwis_common`、`fwis_map_server`、地图和场景复制进来；`expv2/plan` 离线原型及 `exp` 的旧算法包已归档到 `archive/`。当前工作空间从干净 CMake 缓存独立构建通过；启动路径和工具不再依赖相邻 `exp/`。原目录暂时保留。
2. **保存当前版本。** 先把现在的代码、配置、地图和已通过的案例作为 Git 基线。构建目录、日志、大批历史实验结果不放进 Git。
3. **整理三个方法并公平比较。** 先确定三篇论文，再核对现有 `legacy/v1/v2` 分别实现了什么。补足差异后，三个方法各自留一份可运行、可复现的版本。用相同地图、车辆、任务和预算比较，选一个表现较弱的方法当 base，选最有潜力的方法作为主攻。
4. **优化主攻方法，再增加 RL。** 把模式选择、路径和执行时间联合规划做进主攻方法；原版继续保留作对照。之后增加强化学习方法，用同一套案例和安全审核比较。

## 仓库里最终保留什么

- 正式源码、启动和构建说明。
- 三个经典方法、RL 方法及各自配置。
- 实际使用的地图、固定测试案例和测试工具。
- 论文对应说明、最终结果摘要和必要图表。

大批 `relust` 原始日志、重复源码快照、构建产物和缓存先放仓库外归档。不要把整个实验目录直接提交。

## 现在的事实

- 当前默认运行 `expv3` 的 `mode_path_v2`。
- `expv3` 的运行依赖已经迁入当前仓库；旧 `exp` 包已留在 `archive/`，不参与默认构建。
- `expv2/plan` 主要是离线原型和论文资料，不是当前 ROS 主程序。
- `legacy/v1/v2` 还没有确认分别对应哪三篇论文；需要选完论文再映射。
- 当前目录的 Git 状态还没建立为可用仓库；先核实 Git 目录，再做基线提交。
