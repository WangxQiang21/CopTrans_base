# R09 首批代码修复：走廊显示合同与诊断（2026-10-12）

本轮依据第 17 文档开始修改代码，完成显示语义及几个确定的接口缺陷。没有修改地图、车辆尺寸、速度/动力学限值、模式成本或 C++ 搜索。不是全图验收，也没有解决 plan1 连续化可行性。

## 已修改

- `core.py` 增加 `FeatureCorridor` 记录，逐 feature 保存 plan_id、地图签名 hash、station、车辆中心参考位姿、body feature offset/radius、world frame、认证类型及是否参与优化。保留旧 tuple 返回值用于 legacy 兼容；v2 消费并发布记录。`footprint_corners` 明确 margin 是总尺寸增量，每侧一半。
- `optimizer_node.py` 分开 `v3_vehicle_footprints`（0.738×0.500 m）、`v3_vehicle_margin_footprints`（当前 0.778×0.540 m）、`v3_feature_center_disc_regions`（绿色）和 `v3_feature_center_point_or_uncertified_regions`（琥珀色）。车体层按 A/O/Spin 着色。小框未被放大；它们仍是配置空间圆心区域。点已在 map 坐标，Marker 保持单位旋转，避免二次旋转。保留 DELETEALL 清理旧计划。v2 首站模式从第一个连续块补齐；legacy 车体层使用最终 timed trajectory 的邻近位姿。
- v2 quality report 保存所有参考车体角点、逐框角点/尺寸/认证，以及地图签名与物理车体尺寸。走廊角色改为 `feature_center_configuration_space_display`，仍明确 `used_in_continuous_nlp=False`。
- 修复混合 Spin 调用 `add_clearance` 时遗漏的 `pose_has_variables`。
- master 接收 IPOPT/SciPy 的四种可行候选状态；全部仍须重新重定时与独立审核，求解器标签不直接代表可发布。
- 候选阶段通过 finally 保存 endpoint fit、retime、audit 等早退/异常耗时；空候选池抛出携带完整 report 的异常，节点发布 REJECTED quality report，不再只保留最后三条错误。记录候选来源、父候选、平滑参数、模式方向词、审计结果和剩余预算。
- 修复 `ros_map_probe.py` 的 legacy 未初始化变量分支。所有后端保存 timed trace 和实际 Marker points。legacy 原生只检查其承诺的平移/Spin 速度，记录其余动态峰值，但不能把它视为通过 v2 的加速度、jerk、轮系审核；输出 `dynamics_contract=legacy_native_speed_only`。零值角加速度限值按“未启用”解释。方向验收遵循显式 direction policy。
- 更新 S09 smoke 的旧 namespace 断言并检查实际车体边长。新增 `tools/audit_corridor_display.py` 独立复算实际 Marker 与参考记录的对应、车体尺寸/航向、圆心与框角点变换、地图/计划/frame 以及 Marker 时间戳一致性。
