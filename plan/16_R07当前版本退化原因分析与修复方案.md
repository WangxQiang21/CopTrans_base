# R07：当前默认算法退化原因分析与修复方案

日期：2026-10-11  
范围：当前 `run_demo.sh` 默认使用的 `mode_path_v2`，与 `legacy` 的同场景行为对比。本文是诊断和执行方案；本轮没有继续改算法实现。

2026-10-12 交接补充：新增安全走廊框尺寸、航向问题及完整接手状态见 [第 17 文档](17_%E7%AE%97%E6%B3%95%E7%8E%B0%E7%8A%B6%E4%B8%8E%E9%97%AE%E9%A2%98%E4%BA%A4%E6%8E%A5_20261012.md)。方向合同是正反向候选共同竞争、优先少倒车且靠后，必要时允许提前或极端全程倒车；不是全程倒车硬禁令。本文方案尚未执行完成。

## 1. 结论

当前问题不是单一的“权重没调好”。`mode_path_v2` 是一条独立的新规划流水线，接收 C++ 粗搜索给出的一个模式序列，把它转换成连续曲率/斜向角轨迹，再做速度重定时和严格几何审计。转换后的连续曲线如果碰撞，当前流水线缺少 legacy 那些已验证粗路回退、bounded repair 和时序采样失败恢复机制。因此同一条粗路会出现“legacy 能发出路径、v2 找不到可行候选”的情况。

中途爬行的直接原因也已定位：模式/控制切换处很短的曲率过渡使转向曲率的一阶、二阶空间导数变大；重定时器据此限制转向速度、转向加速度，并在后续动力学修正中继续下调速度。它不是横向加速度单独导致的。`lateral_a_max=2 m/s²`，但当前还同时启用了 `steer_rate_max=0.8 rad/s`、`steer_accel_max=1.5 rad/s²`、纵向加速度和 jerk 限制。legacy 的平滑时间采样没有对转向速度/加速度做同等约束，所以两者直接对比播放速度并不公平。

当前代码已对“短控制段导致的爬行”做过一轮局部改善，但这不能代表整体已修好：P12_env4 的 `user_plan3` 从旧结果的 45.30 秒轨迹时长降到 14.76 秒；当前同一计划仍只有 1.232 m/s 峰值，最低速/零速都集中在一次 O→A 模式切换。更关键的是，`user_plan1` 的当前 v2 仍无可行候选，而 legacy 优化器报告找到 `source=fixed` 候选。当前测试工具在 legacy 路径上又有一个独立异常，导致它没保存轨迹并完成最终验收。

我之前把 `mode_path_v2` 设为 `run_demo.sh` 默认后端，却没有先完成同一起终点、同一动力学模型和跨地图的成对验收。这是发布决策上的主要错误。现在不应把这组原型数据称为整体优于 legacy；后续按本文的门槛逐步修复和复测。

诊断输入来自历史 ROS 日志中用户实际运行的 P12_env4 起点和三个终点，记录在 `relust/R07_user_speed_20261011/cases.yaml`。地图、比例、起终点固定，P12_env4 比例为 1.0。

| `user_plan1` | C++ 粗搜索 0.905 s 得到扫掠安全的粗路；连续化后因 `continuous_swept_collision` 被拒，之后还出现 `candidate_evaluation_budget_reserve`，最终 `mode_master_no_feasible_candidate` | legacy 优化器日志报告 `success source=fixed`，5.23 s | 证明该例的失败发生在 v2 连续化/候选恢复阶段，不是 C++ 搜索没有路。legacy 的 ROS 轨迹最终校验尚未完成，不能将该行当作完整通过。 |

R08 的 legacy 探针两次都在 ROS 优化器已经报告成功后，由 `tests/ros_map_probe.py` 抛出 `UnboundLocalError: angular_v`。legacy 没有 v2 格式的 `quality_report`，探针未进入计算 `angular_v/angular_a` 的分支，却在分支外读取它们（文件约第 197–206 行）。因此 R08 有 legacy 优化器日志，没有最终独立扫掠、速度和轨迹时长报告。后续先修复诊断器，再用共同验收器比较；不能把失败的探针状态误认为 legacy 规划失败。

## 3. 为什么转弯或控制切换附近会爬行

连续几何由离散动作的分段常值控制转换而来。在 `continuous_geometry.py` 约第 201–216 行，两个相邻控制值之间用零端导数的平滑过渡，过渡宽度是：

```text
width = min(设定过渡宽度, 0.45 × 左侧动作长度, 0.45 × 右侧动作长度)
```

左右任一动作短，过渡就会缩到几厘米甚至更短。曲率变化量不变时，过渡越短，曲率的一阶和二阶空间导数越大。`user_plan3` 旧结果中的一个过渡只有 0.05368 m，曲率变化量约 1.852 1/m；由配置的 `steer_accel_max=1.5 rad/s²` 得到约 0.0331 m/s 的静态速度上限。完整速度重定时的后续校正又把该区域降到了约 0.0102 m/s。

重定时器不仅按横向加速度限制速度。`continuous_retiming.py` 约第 304–328 行同时使用目标速度、车轮速度、方向盘角速度、方向盘角加速度、横向加速度和车体角速度等限制；约第 480–491 行，动态峰值超过限制时降低相邻速度锚点，然后重新连接速度曲线。修正是单向降低，不会在后续迭代中主动恢复到较高速度。因此短过渡制造的局部尖峰会形成低速区，并可能把低速扩展到邻近区间。

因此，“横向加速度设为 2”并不能排除这种爬行。当前 `translation_alpha_max=0` 只关闭额外的平移车体角加速度约束；它没有关闭方向盘角速度、方向盘角加速度、车轮速度、纵向加速度或 jerk 限制。反过来，也不应为了消除图上的低速而直接关闭所有转向/动力学限制：这些仿真参数尚未用真实底盘能力校准。

`target_v=2 m/s` 目前表示速度上限，不表示每段都必须达到 2 m/s。起终点速度、纵向加速度/jerk、转向执行器约束和路线长度都影响实际峰值。修复应先去掉没有必要的几何尖峰，再由统一的速度规划在安全约束内尽可能维持 2 m/s 巡航；不能把“弯道”本身作为固定降速理由。

## 4. 为什么会无解或偶尔规划慢

### 4.1 v2 绕过了 legacy 的恢复链

`optimizer_node.py` 约第 795–798 行：选择 `mode_path_v1/v2` 后调用 `run_mode_path(...)` 并立即返回。v2 不会继续使用 legacy 的固定走廊 NLP、锚点模式调度、bounded research、时序重采样恢复和已验证粗路回退链。legacy 在约第 2083–2112 行保留独立扫掠验证过的粗路；若局部 NLP 无候选，会继续 bounded research；约第 2265–2298 行，优化后的时序轨迹失败时会再次检查粗路候选。

v2 对“连续化失败的路线”做有限结构变体搜索，但每个变体还要通过 endpoint fit、retime 和完整独立审计。`user_plan1` 的粗模式动作数为 43，粗搜索在 0.905 s 内找到 route；固定控制粗路的 5 mm 扫掠检查通过，但连续曲线在约路径 2.45 m 处发生碰撞。几种 0.1–0.4 m 的平滑带宽离线试验也仍有碰撞。失败发生在“把离散安全路线转换成连续可执行路线并修复它”这一层。继续把平滑带宽盲目调大可能改善这个计划，也可能破坏窄通道的净空。

### 4.2 v2 计算预算花在候选全量验证上

当前 P12_env4 `user_plan3` 后端时间 3.73 s，其中独立审计约 2.24 s（约 60%），endpoint fit 约 0.53 s，retime 约 0.59 s；C++ 粗搜索约 0.84 s。N03 和另一 P12_env4 参考案例中，精确独立审计也占明显比例。每个候选都需要连续轨迹采样、5 mm 矩形车体扫掠检查，并在 1 cm 站点计算精确车体/安全距离。慢点主要在连续候选生成和整条轨迹验收，不在 C++ 粗搜的 0.5 m 锚点。

`quality.search.budget_s=8` 的范围标注为 `optimizer_backend_only`，不是从用户发出目标到收到最终轨迹的总时限；候选评估还保留 2 s、末尾验证保留 0.5 s。候选没有足够预算时会记录 `candidate_evaluation_budget_reserve` 并停止继续试。因此有些失败是搜索预算用完，不是可行性证明。最终报错目前只带 `errors[-3:]`，`optimizer_node.py` 的外层状态只发布最后一行原因；失败候选的分阶段计时也有早退漏记情况。这使得用户看不到“花在哪一步、试了什么、为什么没有结果”。

### 4.3 优化器、代价和验收的目标并未统一

- v2 报告 `initial_is_single_cpp_seed=true`，`region_graph_implemented=false`。粗搜给出的一个模式组合是起点，后续只尝试有限局部结构变体；这不是模式、路径、时间一起优化的全局 MINLP。
- 连续 NLP 固定了模式/方向词、块长度和切换位置，只能在给定的 C1 曲线附近调整控制变量。优化目标含距离场代理净空、A 曲率能量和控制总变差，但实际重定时耗时不随这些 NLP 变量重新优化。它没有速度/时间决策变量，也没有在 NLP 中直接约束完整转向速度、加速度、jerk；末尾独立验收才会拒绝不符合者。
- 主评分里的 `mode_switches`、`oblique_adjustments` 主要用于同分排序，缺少清晰且有量纲归一的切模式事件代价。形状项计算 A 曲率能量；O 模式对角度总变差收费，但没有对应的 O 航向变化率能量项。代价因而没有完整表达用户要求的“少切模式、少转向、O 只在减少 A 曲率或保证通过时使用”。
- `duration_guard_candidates` 会先过滤比当前最快候选慢超过 10% 的候选，再按完整代价选结果。这是额外硬门槛，可能提前排除净空更大或模式更少的路线。
- 静态代码缺陷：`continuous_optimizer.py` 的 `add_clearance` 定义需要 5 个参数，Spin 分支约第 520–522 行少传了 `pose_has_variables`；带可变连续控制的混合 Spin 路径可能抛出未捕获的 `TypeError`。SciPy 后备求解器返回 `converged_feasible`、`iteration_limit_feasible` 等状态，但主流程只接收 `solver_feasible_candidate`，可能丢弃有效后备候选。这不是本次无 Spin 的 `user_plan1/3` 直接失败原因，但进入更复杂模式组合前必须修复。

## 5. 修复原则

1. **先保证可行候选不断链，再谈代价变好。** C++ 粗路、连续拟合候选、局部结构替代和全局优化候选都应保留父子关系和失败原因。粗路通过几何验证不等于通过动力学验证；不得把未经完整扫掠/时间验收的粗路直接发给底盘。
2. **所有候选用同一套终验收。** 矩形车体精确扫掠、边界安全距离、终点位姿、方向/倒车规则、速度/加速度/jerk 和停车事件应由同一版本验收器检查。最终安全仍保持 5 mm 扫掠分辨率，不靠降低检查精度换速度。
3. **把模式选择、路径控制和速度计划接起来。** 当前 C++ 模式序列不能成为后续优化的硬答案；应搜索若干多样的模式词和切换位置，并在每个词下联合调整控制、过渡位置、路径长度和时间标定。
4. **速度低时报告触发限制。** 每个速度锚点应能指出是目标速度、轮速、转向速度、转向加速度、横向加速度、纵向加速度、jerk、模式切换还是终端条件在限速。
5. **不写地图状态机，不取消用户的运行限制。** 所有修复由曲率、净空、可行性、控制变化和运行时间的统一规则驱动。正反向候选共同竞争，优先少倒车、少换向且靠后；必要时允许提前或极端全程倒车。模式变化时允许停车切换，同一模式的普通控制节点不得插入停车/怠速段。

## 6. 分阶段执行方案

### 阶段 P0：冻结输入，修好诊断和失败可见性

**工作项**

1. 修复 `tests/ros_map_probe.py`：无 `quality_report` 时也要初始化轨迹/动态指标，或者根据 legacy 的速度/限值来源独立计算；任何分支都不能读取未定义的 `angular_v`、`angular_a`、`limits`。
2. 将失败报告结构化输出到文件和 ROS 状态：保留所有拒绝候选的来源、父候选、模式词、控制平滑参数、失败阶段、精确原因、阶段时间、剩余预算、最后安全 incumbent。不要只截取最后三条错误或只发布最后一行异常。
3. 修正阶段计时：endpoint fit 失败、retime 异常、审计碰撞等早退也必须通过 `finally` 记入对应阶段耗时和调用数。记录粗搜、转换、候选生成、拟合、重定时、最终审计、发布的端到端总时间。
4. 记录每个速度锚点的限速来源和最终轨迹的每次零速/低速区间；把“模式切换 dwell”“端点”“同模式中间低速”“gear cusp 瞬时过零”分开统计。
5. 固定 R07 三个 P12_env4 起终点作为必跑集，另加 P11_case_b/c、P12_env1–4、N03/N05 的代表案例及未调参的 holdout 起终点。保存代码 hash、地图 hash、完整参数和独立验收结果。

**完成条件**：同一案例无论 legacy 还是 v2 都能生成可读的结构化报告；规划失败可以区分“粗搜无路”“连续化碰撞”“动力学不可行”“预算耗尽”“求解器异常”。诊断报告不能把 `search_success` 当成最终规划成功。

### 阶段 P1：消除同模式爬行，校准速度模型

**工作项**

1. 对控制过渡重新建模：允许过渡站点在有净空的路段内移动和扩展，而不只按相邻离散动作段长度截成几厘米；必要时把很短、没有独立几何意义的粗动作先合并，再生成连续控制。
2. 转向控制变化应满足可实现的曲率/车轮角连续性；重定时器以约束可行的速度曲线求解，避免“发现一次超限就把局部速度永久乘小”的单向累积。局部降速后要能重新连接至目标巡航速度，除非同一条轨迹上的其他硬约束仍限制速度。
3. 允许在长直/净空足够的前中段提前完成必要的航向调整，再进入狭窄末段；选择依据是可达净空和统一代价，不按 P12_env4 的坐标或地图名写规则。
4. 将 `target_v=2` 作为巡航目标，在安全可行区间内惩罚不必要的速度损失；曲率弯道不自动降速。只有实际轮速、转向执行器、加减速、jerk 或碰撞安全约束触发时才允许降速，并把触发项呈现给用户。
5. 与用户要求一致：只有模式切换有驻车/设置时间；同模式的曲率变化、O 角度变化不能产生驻车段。起终点减速和换向瞬时过零单独统计；换向不应造成额外 dwell。对 `steer_rate_max=0.8`、`steer_accel_max=1.5` 等值先明确它们代表的仿真假设，再用底盘实测或用户确认的能力标定，不能为了图好看静默删除。

**验收**：用 `user_plan3` 重放：除 O→A 模式切换外，中段低速/零速应为 0；速度曲线达到目标 2 m/s 的范围和受限区段有明确原因；动力学检查全通过；轨迹扫掠不降精度。采用同一限值分别重定时 legacy/v2 几何路径，另提供各自原生播放结果，避免把两种速度模型混成一个比较。

### 阶段 P2：修复连续化可行性和失败恢复

**工作项**

1. 将粗路作为安全几何 incumbent 管理。粗路只在同一终验收完整通过后才可发布；否则留在内部，继续做受约束的连续化修复。
2. 对连续化碰撞的首个站点建立局部修复窗口，优化过渡位置、过渡宽度、邻近控制值和必要的模式替代；窗口修复结果再做全路径 5 mm SAT 和动态终验收。失败则退回父候选继续试其他窗口，不把已知碰撞路径当成下个 seed 的唯一基础。
3. 将 legacy 的有用恢复机制改造成通用模块供新后端调用：保留经独立验证的安全候选；有限次数的 bounded route repair；时序采样失败后重新尝试几何安全候选；每个模块都使用同一验收契约。不能直接复用 legacy 的未限方向盘动力学时间采样作为 v2 最终发布轨迹。
4. 针对 `user_plan1` 做首个验收闭环：解释第一处连续化碰撞，产生至少一个连续、安全、满足速度/控制约束的候选；否则准确报告为“当前候选生成/修复失败”，不写成全局无解。
5. 修复混合 Spin `add_clearance` 参数遗漏，统一 IPOPT/SciPy 的可行候选返回状态和异常契约，并为这两条执行路径增加同样的终端、碰撞和动力学终验收。

**验收**：`user_plan1` 和 `user_plan3` 都有独立可复算的结果；对能验证的粗路保留其轨迹来源；所有 published 候选 5 mm sweep、终点和动力学通过。失败报告能显示碰撞的路径站点/车体角点及剩余候选。

### 阶段 P3：先定统一 cost，再让模式和路径竞争

优化代价分成硬约束和软偏好。硬约束包括扫掠安全、边界安全裕度下限、终点误差、控制/车轮/加速度/jerk 限值、停车事件及有符号速度合同。普通任务的无必要全程倒车和反复换向由代价抑制，极端可行性任务允许全程倒车。软代价用统一归一化量纲，至少包含：

- 安全裕度：最小值、低净空累计长度和风险峰值；
- 路线长度和实际速度计划计算出的总时间/速度损失；
- A 模式曲率能量、曲率变化率和不必要的反复转向；
- O 模式航向变化总量、角变化率能量，连续 O 转角和不必要的多转角衔接；
- A/O/Spin 模式事件数及每次切换的停车/重设成本；
- 反向行驶长度、反向行驶起始位置和反向中的航向调整；
- 求解时间/候选复杂度作为规划资源项，不能改变硬安全门槛。

根据已有“好轨迹”评价规范先固定优先级和各项单位，再逐项校准权重。代价应支持这样的选择：A 可以顺畅通过的空旷路线不因微小数值收益切成 A+O；如果 O 能减少一段显著转角或使局部路径平滑/可行，则允许使用；连续 O 调角和净空区无意义的多个切换应明显吃亏。最好采用安全硬门槛后按“可行性→净空→模式/转向复杂度→实际时间”的分层或词典序比较，避免单个任意权重用速度换安全。

**验收**：为同一条路径逐项输出 cost 分解，并用人工构造的直路、连续弯、直角入库、低净空走廊和需局部 O 的案例验证成本排序。更改权重不得让碰撞候选变得可选；不得出现无解释的 O 切换或更差 clearance 仅因 10% duration guard 被预先滤掉。

### 阶段 P4：把“局部试模式”扩展为受预算约束的联合搜索

1. 从同一起终点生成多种候选模式词和切换位置，包括纯 A、带少量 O 的路径、必要时 Spin/倒车辅助；不要把一个 C++ seed 当成模式搜索答案。
2. 在一个候选的邻域内同时调整模式切换站、控制过渡、路径局部几何和速度计划。候选间交换可行 incumbent，让连续优化找到的控制/转向改善能反馈到下一轮结构搜索，而不是保留旧 actions 继续生成邻居。
3. 先做有限候选图搜索和局部 MINLP/混合整数邻域；所有候选用统一 exact audit 验证。全局 MINLP 作为后续阶段，只有当 cost、切换变量、时间变量、碰撞证书、可行 incumbent 接口一致后才接入。当前 fixed-topology 几何 NLP 本身不是全局 MINLP。
4. 用安全宽松筛选缩小完整审计次数：快速距离场/粗扫只负责淘汰，不作安全证明；候选排序前缓存几何前缀和相同 sweep 结果；靠前的小集合仍做完全的 5 mm 扫掠和精确 OBB 距离计算。
5. 增加 anytime 行为：一旦得到完整通过终验收的 incumbent，就记录并继续改进，直到全局时间预算；达到截止时返回这个已验收候选，而不是在最后一次候选碰撞时丢掉已有可行路线。

**验收**：固定总端到端时限，候选数和每阶段耗时可解释；至少和 legacy 同样稳定地产生已验证轨迹，之后再逐步改善净空、转向事件或耗时。超时返回已验收 incumbent；没有 incumbent 就返回阶段化失败原因。

### 阶段 P5：跨地图、跨起终点的回归门槛

每次修改使用同一程序自动跑：R07 的三个 P12_env4 目标、N03、N05、P11_case_b/c、P12_env1–4；每个地图另外准备没有调参参与的 holdout 起终点。对每一对输入保存 legacy 和候选 v2 结果。

每个结果分别记录：端到端规划时间、是否有解、几何安全、最小车体净空/低净空长度、实际运动时间、最高/平均/目标速度缺口、所有内部低速和零速位置、模式序列和事件数、A 转向 TV/能量、O 调角 TV/能量、倒车长度及其位置、终点误差、5 mm 扫掠结果、动力学限制峰值和约束来源。

**默认发布门槛**：

1. 所有通过案例达到 2 cm 位置、1° 航向误差，5 mm 矩形车体 swept-SAT 和指定 clearance 门槛通过；动力学符合该次比较明确采用的同一组限制。
2. 除起终点和模式切换外，不存在无解释的停车/低速段；同模式控制节点不能触发零速。模式切换次数、O 连续调角和倒车长度都有报告。
3. 对每个旧版能完成的固定案例，新版不得因为连续化或末尾审计丢掉全部可行解。性能退化和失败都要记为回归，不从统计里剔除。
4. 新版只有在可行率不下降的前提下，才讨论净空、模式复杂度、运动耗时和计算耗时是否更好。求解预算需报告端到端 P50/P95 和最坏值；不能用仅包含 optimizer 的 8 s 预算宣称总规划时间。
5. 默认后端只有在完整回归集过线后才能标记稳定。若仍在原型期，日志和 README 必须清楚显示实验状态，不能再以几个通过 case 推断全场景都改善。

## 7. 执行顺序和交付物

| 顺序 | 交付物 | 退出条件 |
|---|---|---|
| P0 | 可复现案例包、legacy/v2 通用终验收、结构化阶段/失败报告 | 同起终点 A/B 数据完整，工具本身不再提前崩溃 |
| P1 | 连续控制过渡与速度规划修复 | `user_plan3` 无中段无因爬行，只在切模式时停车，约束来源可解释 |
| P2 | 连续化可行性修复和可行候选恢复链 | `user_plan1` 不再因一处连续曲线碰撞直接无解；所有发布轨迹通过共同终验收 |
| P3 | 锁定版 cost 与排序测试 | 成本分解能解释 A/O/倒车/净空/速度选择，不靠地图特例 |
| P4 | 多模式候选与局部路径/模式/时间联合优化 | 有时限内的已验收 incumbent、通过率不低于 legacy，再考虑全局 MINLP |
| P5 | 跨地图和 holdout 回归报告 | 达到第 6 节发布门槛后才把新后端称为稳定 |

在 P0 完成前不再通过单个地图增大/缩小平滑尺度来宣布修复；在 P1/P2 完成前不把全局 MINLP 当成优先救火手段。当前连续优化固定了模式词和切换位置，且在可行候选为空时缺少足够的连续化修复能力；直接增加 MINLP 只会让求解变量更多、失败原因更难定位。
