## 3. 求解过程

1. 精确回放并验收 C++ 粗路径，按新能力 profile 重定时，保存首个合格候选。
2. 对该候选提出不同模式结构，允许删除/替换多个原语和改变控制段数量。
3. 前进 A 连接使用四种 CSC Dubins 候选，不依赖含倒车的最短 Reeds–Shepp 解。未实现 CCC，不声称连接器完备或最优。
4. 即使 A/O 原型暂时不满足 seed 边界姿态，也允许一次全路径 NLP：只固定起终点，中间位置与航向可变，不使用固定 seed 姿态走廊锁住每个节点。
5. 一次 NLP 固定提议的模式，A 内部包含多个连续变量；原 O 控制段的离散节点共享 phi，不能因采样细化额外调角。
6. 该 NLP 使用 ESDF/覆盖圆的代理目标和约束引导，输出仍经过精确回放、受约束时间规划和独立扫掠；模型代理下降不是最终获胜条件。
7. 真实质量评分更新候选队列并产生后续结构提议。已有安全候选不会因精修失败丢失。
8. 8 s 为当前优化后端预算，预留 0.5 s；C++ 搜索时间和首次请求到发布的总预算尚未统一进这个时钟。首个 FEASIBLE 时间是内部候选出现时间，不是已发布给执行器的时间。

## 4. 时间规划与评价语义

`kinematic_sim_v1` 为研究仿真 profile：平移最大速度 0.8 m/s、纵向加速度 0.6 m/s²、路径进度 jerk 2.0 m/s³、横向加速度 0.6 m/s²；角速度 0.8 rad/s、角加速度 0.8 rad/s²、角 jerk 3.0 rad/s³；转向速率 0.8 rad/s、转向加速度 1.5 rad/s²、轮速 1.0 m/s。这些数未做硬件标定。

`a_max` 与 `jerk_max` 描述平移路径进度，横向加速度另行检查，不声称已验证任意笛卡尔向量 jerk 约束。A 段同时限制曲率乘速度/加速度/jerk形成的角运动。初始轮角声明为零、初始模式声明为 A；机械切换延时与轮角变化按顺序执行。实际初始执行器状态接入是后续工作。

所有恒定控制改变暂采用停车、有限时间转向、再加速。控制角等价的原语合并后共用时间律。O 同模式内调角也必须停车重配置，解决原同模式时间组里速度向量方向突变的问题。

当前路径仍由恒定控制原语表示。几何曲率导数只在各移动内部定义；边界跳变单独记录并通过实际重配置时间/事件评价，不能把 `curvature_rate_interiors=0` 解释为全路径连续曲率或整体平滑证明。

`/plan/quality_report` 保存精确原语、quintic 相位、能力 profile 和每个候选的分项。RViz 使用离散点线性插值显示，显示插值也经过覆盖扫掠。声明的精确时间合同与显示插值分开记录；本项目尚未接入真实车辆控制。

## 8. R02：正向优先、局部倒车回退与上游航向重规划

### 8.1 本轮解决的实际断点

旧方向检查在 C++ 产生初值、Python 接收粗解、NLP 长度约束、时间规划、轨迹评价、独立探针及 runner 中均拒绝任何倒车。只增加一个 launch 参数无法接通恢复流程。本轮让上述入口使用同一方向策略，并把评价规范升级为 `trajectory_quality_spec_v1.1`。

```bash
./run_demo.sh --map P12_env1 planning_backend:=mode_path_v1 allow_reverse_fallback:=true
# 正向消融，不允许倒车恢复
./run_demo.sh --map P12_env1 planning_backend:=mode_path_v1 allow_reverse_fallback:=false
```

`planning.allow_reverse_fallback` 默认 true，仅在新后端使用。launch 将后端和方向参数同时传给 planner 与 optimizer，避免 Python 开放回退而 C++ 不提供任何初值。`roslaunch --dump-params` 已核对两节点的 false 覆盖值。legacy 仍按历史纯正向策略运行。

### 8.2 两阶段搜索与验收

1. C++ 保持原来的正向 A/O/Spin 路线图、guided 和独立 lattice 搜索。只在这些搜索都没有得到可行初值时开放倒车恢复；恢复默认最多 30000 扩展、3 s，找到第一条扫掠安全候选即可停止。该预算是额外的粗搜恢复预算，尚非全链路统一 deadline。
2. 恢复 lattice 允许有符号的 A/O 平移及换向；状态增加 `has_forward`，防止全部倒车的低成本标签挤掉已包含前进的合法标签。终点拒绝有倒车却没有前进的路线；插入 Spin 不会绕过这个拒绝。
3. Python 接收混合方向粗初值后先进行正向验收/精修。独立正向初值银行含 CSC 和由起终点几何确定的稳定 O/Spin 候选，不能因为 C++ 给了倒车序列就锁定它。若已有任意独立合格正向候选，含倒车的原始初值不进入竞争。
4. 混合方向粗初值为正向阶段预留后端可用时间的 65%，另为恢复阶段预留时间和一次 NLP 调用；总 NLP 次数仍遵守配置上限。只有正向阶段零合格候选且开关允许，才验收混合方向原始初值。
5. 恢复阶段进一步搜索上游航向调整点：遍历已有平移段的端点/中点，在各点比较几何确定的航向、A/O 恒定控制尾段及必要 Spin，并做廉价扫掠筛选、签名去重和最终独立质量比较。随后可对获选结构做全路径 NLP，中间位置/航向仍自由；NLP 不预先固定 seed 的每个姿态。该候选族是通用初始化器，没有地图编号分支，也不是规定执行 A-S-O。
6. 新结构若恢复出纯正向候选，该候选仍优先。回退候选的完整评价增加 `2 L_reverse/L0 + 1.5 N_direction_switch`；这两项对原纯正向结果均为零。权重为未标定工程起点。
7. 回退 NLP 的负长度保持原符号并自由调整幅度；A 曲率与 O 角度仍可优化。模型目标仍为代理，不以局部求解器的 timeout 或目标下降代替精确回放、时间规划和扫掠验收。

报告包含 `forward_candidate_count`、`allow_reverse_fallback`、`reverse_fallback_activated/used`、前进/倒车距离与换向数，并明确 `forward_failure_is_infeasibility_proof=false`。预算内未找到正向解不等于证明连续空间中不存在正向解。

### 8.3 有符号时间轨迹和独立检查

`TimedPoint.v` 为有符号的路径进度速度，负平移必须发布负值；车体航向不翻转，O 角度仍限定在 `[-pi/2,pi/2]`。quintic 时间律用绝对距离设置速度/加速度/jerk 上限，用原动作符号传播几何和速度；每个方向边界先达到零速，再进入下一段，因此不能用瞬时负速度切换来恢复可行性。

几何评价始终拒绝全程倒车。`retime(..., allow_reverse=True)` 只是生成时序的能力，不意味着该路线能够通过方向合同。独立工具 `trajectory_direction_audit.py` 不导入规划器：它从发布的位姿、时间和有符号速度检查方向一致性、前进/倒车距离、全程倒车及回退来源。动态检查按 `abs(v)` 计算峰值。probe 与 runner 使用该完整方向结果；不再把所有负速度直接视为失败。
