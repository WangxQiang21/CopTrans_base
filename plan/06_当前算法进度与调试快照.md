# expv3 当前算法进度与调试快照

> 快照日期：2026-10-02。本文记录“当前代码实际做什么”、最近一次验证结果与未解决问题，供下一轮调试接续。它是实现状态记录，不代表算法最终性能结论；若代码参数变化，以当前源码和 `catkin_ws/src/fwis_v3_demo/config/params.yaml` 为准。

## 1. 当前判断

当前运行版本是一个分层的 anytime 多模式搜索与连续优化系统：

```text
ROS 地图 / RViz 起终点
  → 多净空权重二维 A* 产生若干拓扑路线
  → 多模式稀疏航点连接图与 O/Spin DP 产生粗候选
  → 可行候选作为上界，限额 Hybrid A* 继续改进
  → 固定事件序列连续优化
  → 锚点 DAG 与终端局部重搜索提出模式/几何替代候选
  → 以当前最好安全候选为起点，交替重建锚点模式图和连续优化（最多 2 轮）
  → 精确运动学重放、整车 OBB swept SAT、终点验收
  → 安全时间化、再次扫掠验证、ROS/RViz 发布
```

它不是完整的“走廊内模式变量 + 连续轨迹变量全局联合优化”，也不是全局最优或 SOTA 算法。当前能在多种场景里生成安全的混合模式结果并对部分案例改进，但候选图覆盖有限，困难目标耗时也不稳定。车库只是窄空间基准；是否倒车不是成功条件。进度应围绕通道可行性、目标位姿误差、连续性/平顺性、净空、代价和耗时来描述，不把单场景结果外推成普遍结论。

## 2. 状态、车辆模型与输出约定

- 参考点始终为车辆中心，即前后轴中心中点；地图、起终点、轨迹和 footprint 均遵循此约定。车长 `0.738 m`、车宽 `0.500 m`、轴距 `0.494 m`，车体相对中心前后对称。
- 模式 A：前后轴反向转向的双阿克曼等效模型，中心曲率 `κ = 2 tan(δ_v) / L`，规划限制最小转弯半径 `0.810 m`。搜索连接使用圆弧/Reeds–Shepp 型有限长度连接，最终以本车精确模型重放复核。
- 模式 O：车身航向不变的斜移，平移方向角为 `φ`；横移是 `φ=±90°` 的特例。
- 模式 Spin：车辆中心固定，航向变化，平动速度 `v=0`。换模式是同一车辆中心位姿上的离散动作。
- 对外最终输出为严格递增时间戳的 `(t, [x,y,v,theta])`，其中 `x,y` 是车辆中心，`v` 是中心平动速度大小。模式标签为内部及可视化信息；当前规划不解轮速、不做控制器或实车执行设计。

## 3. 当前实际算法细节

### 3.1 粗搜与模式竞争

1. 地图先生成安全净空场，并用多组净空权重的 8 邻接二维 A* 产生不同拓扑路线。二维路线只限定大致通道，不直接决定最终车辆轨迹或模式序列。
2. 对各路线提取有限候选姿态与相邻锚点连接。较便宜的 O/Spin 动态规划覆盖多条路线；更昂贵的稀疏混合图只在代表性净空路线竞争 O 平移、Spin 和有限范围的 A 弧。混合图状态额外记录上一个模式、档位和离散控制分箱，避免把换模/倒车/转向历史完全丢掉。
3. C++ 搜索统一比较距离、Spin 等效时间、模式切换、倒车/换向、A 曲率及转角变化、O 角变化与斜移距离等代价。图搜索得到的量化路径恢复后还会按动作序列共同代价复核。
4. 有 incumbent 后 Hybrid A* 仍可尝试降低代价，但默认最多扩展 `1500` 次；未找到任何 incumbent 时，搜索最多可到 `180000` 次。因此前者是改进预算，不是规划的统一墙钟超时保证。

### 3.2 连续优化与局部提议

- Python 优化器先沿粗解给定的事件/模式序列做连续 NLP 精修。求解器上限 `optimization/max_iter=100`；达到上限也只返回待验收候选，不自动视为成功。
- 随后锚点 DAG 在粗路径上最多跨 3 个相邻锚点拟合 A/O/Spin 边，可合并粗动作、改变局部中间几何和换模锚点。边逐条做整车 swept SAT；保留固定序列 incumbent，候选必须按同一代价胜出才可能替代。
- 末端模式/档位切换较复杂时触发有界 terminal-local A/O/Spin 搜索，配置上限 `80` 扩展，并沿目标航向采样少量 approach pose。它不是固定模式状态机，但这仍是目标轴线启发式，候选姿态/连接有限；应视为待泛化的末端局部候选生成器，而不是泊车流程或倒车目标。
- 2026-10-02 新增默认开启的 `joint/alternating_iterations=2`：从目前候选集中代价最低的安全轨迹开始，每轮围绕最新几何重建锚点 A/O/Spin 图，最多对一条有竞争力的新模式/几何序列运行固定模式连续 NLP，再按共同代价、终点和 swept SAT 决定是否更新 incumbent。接受必须严格降低共同代价，失败或无改进会停止并保留原候选。这是受限的交替离散—连续局部联合优化，不是 Bonmin MINLP，也不是全局联合最优；单次连续优化和锚点图原有阶段仍保留。
- `joint_refine` 是 Bonmin 整数—连续联合优化实验开关，当前 `joint.enabled=false`。困难混合模式例仍会内部报错或 `LIMIT_EXCEEDED`，它不是当前主链能力。

### 3.3 代价、平滑和安全裁判

关键当前参数见 `catkin_ws/src/fwis_v3_demo/config/params.yaml`：`w_switch=0.60`、`w_reverse=0.25`、`w_direction=0.25`、`w_steer_tv=0.40`、`w_curvature=0.01`、`w_oblique_tv=0.35`、`w_oblique_use=0.55`、`w_oblique_cruise=0.45`。低角度 O 每米额外按 `0.45·exp(-φ²/(2·25°²))` 与近直行 A 竞争；大角度 O 的使用量按 `0.55|φ|` 计。连续 NLP 内另有较强但只作用于 O 角变化事件的平滑项，以抑制斜移中无意义的小角微调；它不等于车辆硬约束。

这些权重是工程代理参数，不是测得的时间/能耗或经多场景标定的最优值。路径长度是基础代价；Spin 距离等效权重按 `v_demo/omega_demo` 设置。换模、倒车、转角/斜移平滑项暂以加权正则进入总分。

碰撞检查以整车 OBB 对占据栅格的分离轴判据为准。粗搜边、优化重放及时间化轨迹分别检查扫掠；时间化失败时只能回退到再次通过后端扫掠和终点检查的粗解。point-fallback corridor 仅作优化引导，不提供安全证明；最终安全结论来自独立整车扫掠，不来自 corridor marker。

### 3.4 时间化与 ROS 可视化

- 当前 `v_demo=2.0 m/s`、`omega_demo=2.0 rad/s`、`dt=0.10 s` 是规划输出/RViz 回放的演示参数。Smoothstep 平移组平均约为峰值的三分之二，即约 `1.33 m/s`；不是实车速度或控制承诺。
- 粗解与最终解有独立 Path 和模式色带；A/O/Spin 分别为青/橙/紫。HUD 显示当前模式，ego marker 另有航向箭头。走廊 envelope 以离散包络显示。
- 已检查的 RViz warning 根因是若干 ADD Marker 使用全零四元数；现显式给单位四元数，并给删除 marker 设置 map frame/stamp。Smoke 会检查 marker 的 frame、四元数、尺度和点数；自动检查通过不代表所有桌面 RViz 配置都已人工目视确认。

## 4. 最近验证结果（2026-10-02）

本轮单独归档了 S09 预设目标 #2/#5/#7 的联合迭代结果：见 [结果说明](../relust/report.md)、[多目标模式着色图](../relust/s09_presets_2_5_7_modes.png)、[指标 CSV](../relust/metrics.csv) 和 [原始轨迹/status](../relust/trajectories.json)。复现采集脚本为 `tests/capture_s09_results.py`；结果报告逐项列出搜索/优化/墙钟时间、模式距离、共同 cost 分解及本轮迭代变化。该组数据是本次单次 S09 运行记录，不是旧版对照实验；各终点具体是否倒车仅是结果观测，不作为成功/失败判据。

- Python 单元测试：新增交替模式—几何迭代单测后共 24 项通过。
- `catkin_make`：expv3 overlay C++ 编译通过；本轮代码改动在 Python 优化器中，仍执行了 overlay build 验证。
- S09 ROS smoke 覆盖目标 #2、#5、#7，检查终点容差、严格递增时间戳、模式标签、HUD/航向箭头、Marker 字段及时间化后的独立整车扫掠；三个目标均选择 `iterated_joint`，时间化扫掠通过。
- 本轮交替联合阶段最多请求 2 轮，三个目标都接受了两轮代价下降。启动该阶段时记录的 incumbent 与最终共同代价分别为：#2 `13.976 → 13.308`（下降约 4.8%），#5 `19.561 → 19.166`（约 2.0%），#7 `15.786 → 15.751`（约 0.2%）。这些起始分是进入新迭代阶段时的最优安全候选分，不是 C++ 原始粗解分，也不是与旧版本的严格消融对照；应视为本次运行内部的迭代收益记录。
- 新阶段使三个目标优化总耗时为：#2 `2.28 s`、#5 `3.30 s`、#7 `2.20 s`；其中交替联合集成耗时约 `1.27 s`、`1.54 s`、`1.48 s`，含候选图与最多两次 NLP。它能提供额外局部改善，但对后端时间有明显开销，尤其 #5；尚未证明该收益/耗时折衷值得成为所有地图的默认设置。
- 后续加入交替阶段的低收益提前停止：仍接受每个严格降 cost 且通过终点/扫掠验证的候选；若本轮相对改善低于 `0.25%`，跳过下一轮。S09 单次复测中 #7 在一轮后提前停止，最终 cost `15.751` 和模式序列与前次两轮结果相同，优化器时间 `2.14→1.44 s`（约少 `0.70 s`）；#2/#5 本轮未触发，仍执行两轮，分数没有变化。此为单次结果，尚需多场景配对复测。
- 调整了 S09 全部 7 个预设终点的姿态，增加与普通正向入位不同的对比难度：底排 #1–#3 航向由 `-90°` 翻为 `+90°`；R2A 从原本落在占据车体上的 `(7.25,4.00)` 修正到红色空车位中心 `(6.58,4.00)`；R2B 与两个 45° 目标保持其对应非正向姿态。场景 hints、`scene_meta.yaml`、预设回归与结果采集脚本已同步。此设置用于形成具有挑战性的末端位姿基准，不要求以倒车完成。
- 重新采集了全部 7 个目标。独立 OBB-SAT timed sweep 首次发现 #6 在斜移段一个 10 mm 内部复验间隔漏掉的窄碰撞；最终时间轨迹复验步长已收紧为 2.5 mm（配置 `collision/timed_sweep_corner_step`），随后 7/7 个目标通过独立的 5 mm 扫掠复验。#6 使用较保守的固定序列候选回退时也通过；此次加严仅作用于最终时间轨迹检查，不改粗搜目标代价。
- 新增末端姿态图拒绝原因统计。#5 的 staging-pose 图检查 110 个入口姿态，其中 105 个没有安全 A/O 接入；仅形成 2 个末端运动学候选，均没有击败安全 incumbent（最佳候选分数 `27.258`，当前最终 `19.166`）。该统计仅说明当前终端候选图覆盖/代价竞争的局限，不代表应强制搜索倒车路线；后续应直接检查目标位姿误差、末端连接可行性和与基线相比的路径质量。
- #2（底部中间目标）：最终有 A/O/Spin，轨迹约 `6.45 s`，平移平均约 `1.34 m/s`，最近一次优化约 `0.71–0.98 s`，扫掠通过。
- #7（顶部斜位）：最终有 A/O/Spin，优化约 `0.70 s`，保留约 `2.39 m` 斜移，扫掠通过。它说明当前代价没有把斜移整体禁掉。
- #5（MID_B 开口向南）：本轮最终为 O/Spin、没有倒车，平移平均约 `1.33 m/s`，扫掠通过。该模式序列本身既不算成功也不算失败；目前缺少统一 Ackermann 基线、多场景配对和末端误差/曲率/净空对照，因此不能仅凭是否倒车评价算法。
- 覆盖更广的先前回归中，粗搜约 `0.13–1.39 s`、优化后端约 `0.43–2.82 s`。这些时延随目标而变；不是硬实时保证。
- 一次真实目标回归中，锚点候选把揉库目标共同分从 `16.445` 降到 `16.213`（O/Spin/O），顶部斜位从 `14.944` 降到 `14.673`（A/O/Spin）；另一个揉库目标候选更差，保留固定序列 incumbent。这是局部案例，不足以证明权重普遍更优。

## 5. 卡点与建议排查顺序

1. **把末端质量作为通用规划问题评估。** 对所有终点报告位置/航向误差、最后一段曲率与曲率变化、局部净空、连接可行率；检查目标附近的候选姿态与通道拓扑覆盖。目标轴线采样只能作为一种候选启发式，不能固化成泊车状态机，也不应以是否倒车作为优化方向。
2. **评估联合迭代的收益/耗时折衷。** 本轮内部共同代价下降约 `0.2–4.8%`，新增后端耗时约 `1.3–1.5 s`；#7 收益很小，#5 仍未解决。下一步应对更多目标做关闭/开启配对消融，并按“只有找到有潜在收益候选时才继续第二轮”或按剩余时间动态截断，避免对已收敛目标固定支付两轮开销。
3. **控制求解耗时尾部。** 区分 C++ topology/route graph/Hybrid A*，Python 固定序列 NLP、锚点候选和 SAT 各阶段耗时；不要只看总时间，也不要先降低 100 次迭代或安全采样密度。此前 60/80 次 IPOPT、放大 knot 间距的消融损害困难目标结果或没有足够时延收益，故已回退。
4. **检验代价是否泛化。** 对多个窄口、不同终点航向的地图做权重扫描和 Pareto 对照，并与相同车辆/终点/安全条件下的 Ackermann-only 基线比较；记录可行率、末端误差、时延分位数、碰撞拒绝、路径长度、A/O/Spin 占比、模式切换、曲率总变差、O 角总变差和最小净空。倒车距离可以作为行为描述指标，但不设为必须增加或减少的目标；不要把离散原语数直接称为“打方向次数”。
5. **避免夸大联合优化。** 当前固定序列 NLP 是连续子问题；交替法和 DAG 是有限局部模式/几何候选，都不能任意跨同伦类。完整走廊内离散模式—连续几何联合主问题仍是后续研究，不应把 Bonmin 开关打开后的一次成功当成解决。
6. **安全证据分层描述。** 当前通过的是静态 OccupancyGrid + 理想模式运动学 + OBB swept SAT 的仿真几何安全检查；point-fallback corridor、RViz 视觉无碰撞或速度演示都不能替代该检查，也不能推导出实车安全。

推荐每次算法改动按“单测 → catkin 编译 → #2/#5/#7 smoke → RViz 目视检查”的顺序回归，并在记录中注明改动参数、目标、粗搜各阶段耗时、后端耗时、共同代价及独立 sweep 样本数。若某一检查未执行，应明确标成未验证，不用其它层的通过结果代替。

## 7. 2026-10-02：航向对齐走廊与论文地图数字化

### 走廊表达更新

此前 `build_corridors()` 对每个车身特征圆心扩张世界坐标系 AABB，因此 RViz 每个走廊框都是水平/竖直边。特征圆心的位置计算已经使用参考位姿的 `theta`，但框方向没有使用它。现在仍先在障碍膨胀后的自由栅格上构造、验证 AABB，再取其中一个按车辆长宽比缩放、以参考 `theta` 旋转的内接矩形：

```text
body feature point (x,y,theta_ref)
  -> safe world AABB [xmin,xmax] × [ymin,ymax]
  -> inscribed local rectangle (cx,cy,h_long,h_lat,theta_ref)
  -> identical local-frame constraints in NLP and polygon vertices in RViz
```

优化器把动态车身特征点投影至该参考位姿的纵/横向坐标，限制在矩形半长、半宽内；RViz 使用同一组矩形顶点。该旋转矩形是已经认证 AABB 的子集，不能凭显示扩大可行空间。走廊仍是基于整条粗解/候选参考序列一次性构建的优化约束，不是车辆执行中的在线重规划；它也不是按 A/O/Spin 分别生成的模式专属空间。

本轮将有效 disc corridor 的 RViz 离散包络按最终轨迹局部模式着色，复用轨迹配色：Ackermann 青蓝、斜移橙色、Spin 紫色。每个走廊 knot 通过车身特征中心均值和参考航向匹配到最近的最终轨迹位姿，再取该处动作模式；航向项用于区分 Spin 时同位置的姿态。颜色表达“这个共享走廊 knot 附近最终选择了什么模式”，不是三套独立模式走廊，也不意味着不同模式能在该 knot 任意互换。point-fallback/未知走廊仍统一用琥珀色作为非认证提示。最终静态安全依赖独立整车 OBB swept-SAT。

为避免错误呈现，交替优化结果现在保留实际 `disc` / `point_fallback` 类型；之前的通用字符串 `disc_or_point_fallback` 会被 RViz 当成 fallback 而显示成琥珀色，这一元数据已修正。

### 论文地图数字化

原 PDF 只有带轨迹的绘图，没有作者原始 occupancy grid。用户发来的四张 RViz 图对应：图1 P16 Figure 22，图2/3/4 分别为 P11 Fig.5(a)/(b)/(c)。此前地图只按坐标轴刻度还原米制范围，忽略论文车辆比本项目小车大很多，造成 RViz 中车辆相对通道显得过小。修正为保持栅格障碍布局不变，只改 `map.yaml` 的统一分辨率/原点，使全图在 x/y 上等比例缩放；不再做障碍膨胀、局部瓶颈或矩形化。地图渲染仍为 360 dpi，细线轨迹和小抗锯齿孤点被过滤。

比例基准来自论文参数表和本车参数：P11 仿真车宽 1.675 m，对应因子 0.500/1.675=0.299；P12 仿真车宽 0.620 m，对应因子 0.806；P16 仿真车宽 2.0 m，对应因子 0.250。P16 Figure 22 另按用户要求，以原图左侧纵向通道约 5.74 m 映射到 1.0 m（两倍本车宽），故该图比例因子 0.1741。比例中心取原图坐标范围中心，障碍像素布局不变。起终点需要在新坐标系中重新设置，旧坐标不能直接复用。总览采用统一 16 px/m，并画出 0.738×0.500 m 车体参照。
