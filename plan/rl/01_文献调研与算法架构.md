# 第四版：基于强化学习的多模式路径规划调研与架构

调研日期：2026-10-26，Asia/Shanghai。开发分支：rl-mode-path。父分支：continuous-mode-path，起点提交 c90e981。

**当前交付是设计与执行方案，尚未实现或训练强化学习规划器。本文所有性能门槛都是拟定验收目标，不是实验结果。** 实施顺序见[执行方案与验收标准](02_执行方案与验收标准.md)。

## 1. 先看结论

第四版建议采用 **“带动作掩码的 PPO 模式—路径联合决策 + 现有连续轨迹后处理 + 独立整车审核”**。

学习策略观察地图、起终点、当前姿态与模式，逐次选择一个短运动段。每个选择同时确定运动模式、方向、距离以及曲率或斜移角；累积这些运动段得到完整路径。因此，学习策略承担路径生成和模式选择两个任务。生成后的路径复用 v2 的连续化、边界拟合、时间规划和审核。

第一阶段选用离散的多模式运动原语库和 MaskablePPO。等这一版在未见布局上通过验收，再考虑把距离、曲率、斜移角改为连续参数。直接学习四个轮子的转向角、转速和底盘跟踪控制，会把当前的规划问题扩大成控制问题，第一版不采用这条路线。

| 关键决策 | 本方案 |
|---|---|

### 3.2 四轮独立转向相关工作：要区分规划与跟踪

Wang 等的 4WISD 分层框架以 SAC 输出连续车体速度，低层模糊控制器负责运动学约束与模式处理。本项目可借鉴分层方式；第四版则显式学习 A/O/Spin 和几何路径段，让模式决策直接承担规划时间代价。[原文，2025 预印本](https://arxiv.org/html/2508.16574v1)

Bao 等 IROS 2025 的题目是 Deep Reinforcement Learning-Based Trajectory Tracking Framework for 4WS Robots Considering Switch of Steering Modes。它与模式切换有关，但研究层次是轨迹跟踪。本次 IEEE 页面受访问校验限制，未获得可核实全文，因此仅列入补读清单，不以其中未核实的训练细节或性能数值作为本方案依据。[正式 DOI 入口](https://doi.org/10.1109/IROS60139.2025.11247526)

Hua 等 2024 工作研究 4WISD 路径跟踪的强化学习辅助控制。它适用于未来控制层扩展，不承担本轮静态地图中的完整多模式路径生成任务。[原文](https://www.mdpi.com/2227-7080/12/11/218)

当前 v2 参考的 Bao 等 2026 框架强调模式增广搜索与模式一致分段轨迹处理。第四版继承后者的工程能力，把前端提议机制改为学习策略；文献框架与当前仓库的具体实现范围需要分别描述。[论文 12 原文](https://arxiv.org/abs/2608.29108)

### 3.4 为什么选 MaskablePPO 作为第一版

它支持现成的离散动作掩码，适合“有限模式 + 一组明确运动段”的工程起点。更重要的是，动作可以直接映射到当前 Action，训练环境、候选输出和公共审核之间不需要再学习一个运动学转换器。

代价是采样量可能较大，固定动作库也可能限制可达性。因此第一版必须先验证原语库能覆盖目标任务，再开始大规模训练；一旦掩码计算比推理更贵，要优化验碰和候选复用，不能把网络推理毫秒数当作整条规划的耗时。

官方 MaskablePPO 文档当前不支持循环策略；并行环境需要在环境内部实现 action_masks，评估要使用支持掩码的评估器。第一版采用前馈网络和显式路径历史特征，不直接拼接一个不受支持的 recurrent policy。[官方文档](https://sb3-contrib.readthedocs.io/en/master/modules/ppo_mask.html)

## 4. 四个版本之间的关系

| 版本 | 当前分支 | 主要路径生成方式 | 第四版与它的关系 |
|---|---|---|---|
| legacy | multimodal-hybrid-astar | 模式增广 Hybrid A* 与旧后处理 | 教师来源、传统对照、可选显式兜底 |
| v1 | mode-path-constant-primitive | 恒定原语候选与分段处理 | 教师来源、传统对照 |
| v2 | continuous-mode-path | 模式结构候选、连续化与段级计时 | 提供第四版的连续表示、最终计时与审核 |
| RL | rl-mode-path | 策略逐段生成模式和几何，再统一后处理 | 第四种方法；本次仅完成设计 |

不预先指定哪一种是“最弱基线”或“最好方法”。这应由同口径实验决定。论文中分别报告各分支原生流水线，以及共用后处理条件下的前端对照。

现有共享代码仍含历史后端。第四版实施时新增独立提议器与小型公共完成器，避免把训练、推理和候选枚举继续塞进 ModePathMaster。

论文可以把第四版暂称为“执行时间感知的强化学习多模式路径规划”。需要验证的三个假设是：学习策略能减少重复结构搜索；真实计时反馈能减少无收益的模式切换；完整车体动作掩码与公共完成器能保持输出可用性。通用的“RL+优化”和“动作掩码”已有先例，不能单凭组合这两个模块就宣称首次提出。4WIS 显式模式—几何决策、切换物理时间反馈及其相对现有方法的实际收益，才是本项目应重点验证和论证的内容。

### 5.1 学习策略具体决定什么

策略不是只输出一个模式标签。它选择 a=(m,d,l,c)：

- m：A、O 或 Spin。
- d：平移方向，受共同方向规则约束。
- l：本次平移距离；Spin 时改为转角。
- c：A 曲率、O 斜移角；Spin 为零。

连续多步的选择决定绕障方向、绕行拓扑、转弯位置、何时斜移、何时旋转，以及最终到达目标的姿态。全局二维引导场只是观测和奖励势函数，不能固定模式，也不作为车体可通过的证明。

第一版可以从同一起点生成 K=1 个确定性候选；随后比较 K∈{1,4,8} 的有界多候选推理。候选去重后用最终执行时间排序。不能把策略概率最高等同于执行时间最短。

### 5.2 为什么保留连续后处理

离散运动段之间的控制不连续、末端格点误差和车体扫掠问题已有工具处理。直接复用能把主要研发工作集中到策略与数据。

但“原语重放无碰撞”不能保证“连续化后仍无碰撞”。平滑会改变几何，末端投影也可能影响整条路径；任何拟合、优化后都必须重放、复核，失败则尝试另一候选，不能直接发布原语验碰的证书。

当前 continuous_optimizer 主要针对固定模式、方向和块长调整控制，并非同时优化全程模式序列、段长和时间的全局求解器。在当前 minimum_time + mode_switch_only 条件下，有些固定结构 NLP 会被跳过。第四版需要学习的正是模式、段长、旋转量与路径布局；不能假定调用一次现有 NLP 就能消除这些决策的时间损失。

## 6. 任务建模与动作空间

### 6.1 环境状态与时间

环境完整状态包括：

S=(M,q,q_goal,m_prev,d_prev,n_reverse,spin_since_translation,path_prefix,budget,profile)。

q 是车体中心 (x,y,theta)，M 为占据地图；path_prefix 保存已生成动作，既用于方向规则也用于终局重定时。不同动作覆盖不同距离和转角，具有不同物理持续时间，因此从物理执行角度适合按段的半马尔可夫描述。

第一版将训练步理解为“规划决策步”，采用有限回合、gamma=1 的未折扣累计代价。这样无需把每步都假设为相同物理时长。若后续改成连续时间折扣，应采用与持续时间一致的折扣，并一起调整 GAE/回报计算，不能仅把标准 PPO 的 gamma 改一个数值就称为时间一致的 SMDP 实现。

策略观测是完整状态的压缩，尤其是地图和路径历史的压缩会丢失信息；因此不声称前馈网络获得严格完全可观测状态。第一版用历史轨迹栅格、最近动作和共同规则状态缓解这一问题，若长距离死循环仍严重，再评估支持掩码的循环策略或规划树。

### 6.2 第一版动作库：80 个候选

取 L=车辆长度=0.738m，R=车辆 r_min_ack，均从车辆配置读取。

| 模式 | 控制参数 | 距离/转角 | 方向 | 数量 |
|---|---|---|---|---:|
| A | kappa∈{-1/R,-0.5/R,0,0.5/R,1/R} | l∈{0.25L,0.5L,1.0L} | 前进、后退 | 30 |
| O | phi∈{-90,-60,-30,0,30,60,90}° | l∈{0.25L,0.5L,1.0L} | 前进、后退 | 42 |
| Spin | control=0 | delta_theta∈{±15,±30,±60,±90}° | 由转角符号表达 | 8 |
| 合计 | | | | **80** |

以上是拟定起点，不是最终分辨率。原语库可达性检查若失败，应先增补角度、短距离或末端解析连接，再训练。不能把动作库无法表达的任务归因为 PPO 没学好。

动作直接构造现有 Action(mode,amount,control)。O 的 amount 正负与 phi 的组合严格遵循 advance；不另外发明“倒车角度”的解释。forward_only 时屏蔽负平移量，Spin 正负仍保留。

设有符号平移量为 l，A 的 theta'=theta+kappa*l，则复用的几何转移为：

$$
f_A(q,l,\kappa)=
\left(x+\frac{\sin\theta'-\sin\theta}{\kappa},
y+\frac{\cos\theta-\cos\theta'}{\kappa},\theta'\right).
$$

kappa=0 时取直线极限；O 为

$$
f_O(q,l,\phi)=(x+l\cos(\theta+\phi),y+l\sin(\theta+\phi),\theta),
\qquad
f_S(q,\Delta\theta)=(x,y,\theta+\Delta\theta).
$$

角度归一化沿用公共函数；限制 |kappa|≤1/R、|phi|≤pi/2。上述方程只决定空间路径，段的持续时间和速度由公共重定时器生成。第一版不需要对几何审核或数值完成器反向传播，终局奖励即可给 PPO 提供反馈。

不设置可无限等待的动作，也不让策略自行宣称到达。到达由共同位置、航向与审核条件决定。最终允许 Spin；是否使用取决于可行性和总执行时间。

### 6.3 掩码和局部安全检查

有效动作须同时满足：

1. 车辆能力与方向配置允许该动作。
2. 地图内完整矩形车体运动扫掠可通过，包含安全裕度。
3. 共同不揉库规则允许该动作。
4. 不违反明确的回合预算。

共同不揉库规则以 action_shunting_violation 为准：最多一次平移方向反转，反转前的两段平移之间须有真实、净转角非零的 Spin；单纯插入 Spin 标签不满足条件。当前实现判断的是归一化后累计 Spin 转角，不是“出现过一个 Spin 动作就算通过”。

Spin 的碰撞检查必须覆盖矩形车体旋转扫掠。只检查车体中心、旋转前后两个矩形或小内切圆都会漏掉中间旋转碰撞。模式重配置时车体静止；Spin 运动时车体转动，两者分别计时、验碰。

掩码只证明当前短段在当前模型与检查精度下可接受，不证明后面一定可到达。全掩码时结束为失败或启动显式兜底，不调用全无效 softmax，也不假装生成成功。

第一版可对 80 个动作直接检查，先建立正确性参照，再优化吞吐。优化顺序是便宜的方向/规则筛选、可证明的距离界、复用车体坐标系运动模板、对剩余动作调用精确检查。姿态取整缓存和粗栅格近似不能成为放行碰撞动作的依据。

## 7. 观测与策略网络

第一版使用小型 CNN + MLP，避免在训练数据不足时先堆大型 Transformer。

| 输入组 | 拟定表示 | 作用 |
|---|---|---|
| 局部地图 | 64×64，车体坐标系，约覆盖 8L×8L；占据/距离/路径历史等通道 | 近障碍几何；栅格越界按障碍处理 |
| 全局地图 | 64×64 保持长宽比的占据/目标/历史通道 | 长距离布局信息；缩放仅用于网络观测 |
| 全局引导 | 从目标计算的二维距离场、路线预览点 | 减少长走廊与迷宫中的盲目探索；不是动力学可行路径 |
| 目标与车体状态 | 相对 x/y、sin/cos 航向差、当前模式、方向、车辆比值 | 统一物理量与角度周期表示 |
| 规则和历史 | 剩余步数、反转次数、累计 Spin、最近 K=8 个动作、访问次数统计 | 共同动作规则与反复绕圈识别 |
| 动作信息 | 80 维掩码；可附动作端点、控制和距离特征 | 让网络知道可选动作及其几何差异 |

占据地图用于策略时可以缩放、旋转裁剪；真正碰撞检查仍用原始地图分辨率与原始坐标。地图整体缩放时车体尺寸保持固定，沿用 run_demo 的比例语义。

Actor 输出 80 个 logits，按掩码重新归一化；Critic 输出状态值。行为克隆也用同一掩码概率。首版使用固定动作编号和普通输出层，后续只有在动作库需要变化时再引入候选共享评分网络。

MaskablePPO 支持 Dict 观测，可定制特征提取器。第一版不修改 PPO 的核心概率比计算；掩码必须随 rollout 保存，并在更新时保持和当时动作选择一致。[官方实现文档](https://sb3-contrib.readthedocs.io/en/master/modules/ppo_mask.html)

## 8. 奖励：对齐“可行后执行时间最短”

### 8.1 评价顺序与训练代理

最终候选选择遵循：

1. 车体碰撞、终点、运动限值、方向规则全部通过。
2. 最小化公共重定时得到的 T_exec。
3. 近乎等时再比较路径质量；安全裕度最低要求始终是硬门槛。

训练中使用数值奖励近似这一目标，checkpoint 则先按验证成功率、再按成功任务执行时间选取。有限的成功奖励不能严格实现期望意义上的词典序优先级，不能把“大碰撞惩罚”当作安全证明。

### 8.2 每步时间代理与终局校正

逐步近似代价取：

$$
\hat t_i =
\begin{cases}
|l_i|/v_{target}, & m_i\in\{A,O\},\\
|\Delta\theta_i|/\omega_{spin}, & m_i=Spin
\end{cases}
+\tau_{switch}\,1[m_i\ne m_{i-1}].
$$

它忽略加减速和连续段耦合，只是稠密反馈。默认初始模式 A，tau_switch 来自公共车辆配置。

每步奖励：

$$
r_i=-\hat t_i/T_0+\eta\,[\Phi(s_{i+1})-\Phi(s_i)].
$$

Phi 可采用归一化二维到目标距离的负值。所有真正终止状态的势置为零，使有限回合 gamma=1 下势函数项对固定起点只留下常数；不额外奖励逐次经过某个路标。二维距离场不可达值应截断并给出任务生成标记，避免出现无穷奖励。

成功回合结束后，将整个动作序列连续化、拟合、重定时并审核，用实际 T_exec 做一次校正：

$$
r_{terminal}\mathrel{+}=B_{success}
+(\sum_i\hat t_i-T_{exec})/T_0.
$$

于是成功回合的累计主奖励为 B_success-T_exec/T0，再加与动作无关的起点势常数。这样，平移加减速、Spin 运动与模式驻留都由最终计时统一反映。

拟定数值起点：T0=10s、B_success=50、B_fail=50，任务执行时间上限暂取 300s。超过约定上限是任务失败；这些值在第一轮基线测量后冻结。失败回合不获得时间校正奖励，而是保留已付出的时间代价并添加失败惩罚。数值缩放、回报归一化和熵奖励的最终配置要随实验记录。

### 8.3 避免把时间计算错

- RL 每作一次决策不代表车辆停车一次；相邻同模式同方向动作先合并为连续模式段。
- mode_switch_only 默认事件固定 0.3s，不另加一次 setup；受限动态 profile 的延长由同一公共函数处理。
- 0.3s 已计入 T_exec，不再默认叠加一个很大的切模式惩罚。额外“切换次数正则”只能做注明目标变化的消融，主实验系数为零。
- 不给 Spin 固定负奖励。它是否值得用，取决于旋转时间、换模时间与绕行时间的总和。
- O 与 A 不按中心点净空奖励排序，避免重现“Spin 看起来更空旷就优先切模式”的问题。
- 主实验不以曲率直接降低目标速度；采用现有 mode_switch_only profile。受限动态 profile 作为独立对照，数据和模型身份都须区分。
- Spin 的中心速度 v=0，但航向在改变，不能将全部 Spin 时长算作静止切换停顿。

### 8.4 训练奖励与部署后处理的范围

首轮训练终局调用连续化、拟合、公共重定时及完整审核，不在每一步运行全路径 NLP。该奖励对应“连续化后的候选时间”。

部署时可以再作固定结构几何修复和多候选比较，后处理可能改变候选排序，必须报告修复前后时间和学习单独贡献。若这一偏差明显，再增加末期带相同完成器的训练：终局完成器返回后才计算当批 advantage，不将事后到来的新奖励塞入已经消费的 PPO rollout。完成器超时需记录失败阶段，不把旧模型的估计时间当成已审核时间。

## 9. 训练数据与训练路线

### 9.1 首版用现有几何仿真训练

训练循环直接使用 Python 几何内核与地图，省去 ROS 消息和 RViz 开销。这里学习的是静态地图路径规划，不需要一开始搭建 Gazebo、CARLA 或四轮动力学仿真。后续真实车辆控制与仿真到现实迁移属于另一阶段。

### 9.2 教师数据

三个现有分支都可以离线提供可行轨迹。教师路线需要经过共同完成器重计时后再择优；不能比较不同时序契约下的原生 duration 后直接认定谁更优。

教师连续动作通常不在 80 动作库上。不能简单把曲率和角度取最近格点后沿用原证书；必须在同一动作库中重新搜索或局部重编码，并精确重放到达和验碰。无法对齐的轨迹记录为 alignment_failure，不能给策略错误标签。

建议顺序：一小批可对齐演示做行为克隆 → 策略环境交互微调 → 必要时在策略访问状态上增量教师查询。教师并非全局最优标签，训练目标与最终评估仍允许策略发现不同、更短执行时间的路线。

### 9.3 训练任务分布

从少障碍、单模式、短距离开始，逐步加入：

1. A 模式可直接通过的转角，学习不用多余切换。
2. 侧向空间适合 O 的任务。
3. 需要 Spin 才能有效改变车头方向的任务。
4. 多障碍组合、窄通道和长距离全局绕行。
5. 起终点姿态扰动、地图比例变化、不同可行净空与前后向要求。

Spin、O 必要任务与 A 足够任务都要出现。起点、终点、航向、障碍尺寸和拓扑随机化时，先保证初末车体不碰撞。二维连通只能证明点路径存在，不能证明满足车体和方向规则的路径存在。

### 9.4 训练、验证、测试分开

现有 11 张地图的预设任务作为工程回归集，已经被长期用于调试，不能称为从未见过的盲测集。

正式泛化实验优先使用程序生成布局：按原始布局 ID 划分训练/验证/测试，然后再做旋转、平移、缩放和起终点增广。同一布局的不同增广版本不能跨集合。P11 的 map01–03、P12 的 map04–07、P16 的 map08–09 分别有共同来源；使用真实地图划分时也必须按来源家族处理。

建议起点：训练按需采样至少 1,000 个独立生成布局，验证 200 个固定任务，测试 500 个固定任务，并留出完全未参与训练的拓扑家族作 OOD 测试。数据量是实施初值，P0/P1 生成并检查清单后冻结。

测试任务先按静态初末合法和二维连通筛选，保留“参考规划器未找到证据”的未知可行任务。全量任务与“已有独立可行证书”的子集分别报告，不用 RL 自己的成功与否决定哪些任务进入测试。

## 10. 在线推理与 ROS 接入

### 10.1 不等完整 C++ 搜索结束再调用 RL

当前默认流程是 C++ 搜索输出 PlanSeed 后 OptimizerNode 才工作。如果第四版也等到整条传统路径生成后才调用策略，学习网络很快也无法消除前端搜索耗时。

RL 分支正式接入时，由新的 RL 提议节点接收地图和起终点，直接触发策略；默认不启动完整 C++ 规划节点。二维引导仍可共享地图算法，传统完整规划只用于显式兜底或离线教师。

### 10.2 消息与进程边界

ROS Noetic 节点继续使用当前 Python 3.8。训练与推理用独立 Python 3.10+ 环境；建议选定稳定 Python 3.11 环境，锁定通过验证的 PyTorch、SB3、sb3-contrib、Gymnasium 版本。

原因是本次环境盘点显示：系统 Python=3.8.10，尚未安装 torch/gymnasium/stable_baselines3/sb3_contrib；nvidia-smi 存在但无法连接 GPU 驱动，尚不能安排依赖 GPU 的训练承诺。官方当前 SB3 master 安装页要求 Python 3.10+，说明直接向 ROS 系统解释器安装最新版并不合适。[官方安装说明](https://stable-baselines3.readthedocs.io/en/master/guide/install.html)

ROS 桥接节点通过本地 Unix socket 与常驻推理工作进程交互。请求包含 plan_id、地图哈希与物理分辨率、起终点、车辆/profile 哈希、预算；回复包含候选动作、来源、模型哈希和计时。地图按哈希缓存，避免每个决策重复序列化整张地图。

当前 PlanSeedCandidates 只装一个 proposal_primitives，不能直接表示 K 条独立路径。K=1 原型可复用 PlanSeed；K>1 时新增明确的 CandidateSet 消息，避免把多个候选展平成一条动作序列。具体字段见执行方案。

新目标取消旧请求；ROS 只接收当前 plan_id 的结果；map/profile/model 身份不符则拒绝。模型缺失、动作库不匹配或工作进程超时应显示原因，不能静默把 v2 输出标成 RL。

首版请求的起点约定为静止 A 模式。当前连续重定时器与对应审核也把初始模式写为 A；若未来支持从实际 O/Spin 状态重新规划，需要同时扩展请求、训练初始分布、重定时和审核的 initial_mode 接口。在此之前应拒绝不受支持的初始模式，不能直接把正在运动的 RViz 标记当成新的 A 模式起点。

## 11. 推理预算与性能瓶颈

完整规划耗时应包含：

T_wall=T_map+T_guide+T_mask+T_network+T_rollout+T_connector+T_fit+T_opt+T_retime+T_audit。

启用兜底时继续加上 T_fallback，不能从端到端耗时里扣掉。冷启动模型加载与热态请求分别测量。GPU 推理需正确同步后计时。

第一版设置有限决策步数、候选数和终端连接预算；任何部件都受全局 deadline 约束。对预测概率相近的候选有限展开，不作无限策略回滚。

潜在瓶颈首先是动作掩码中的扫掠查询，其次是重复地图编码、连续化失败修复和候选审核。当前 SegmentTimingCache 可以复用相同运动块的局部求解，但地图、姿态相关证书仍需逐路径复核。

不承诺训练或规划速度数值。先做 200,000 步小规模试验，测出实际环境 steps/s、审核成本和成功率，再决定 2M、10M 步等预算。总训练时间近似 N_steps / 实测吞吐率；还需另计教师生成、终局处理和验证。

## 12. 对比实验：证明第四版的贡献来自哪里

### 12.1 两种比较口径

**原生流水线比较：** 三个已有版本与 RL 的完整运行结果，衡量用户实际体验。明确原生时间规划差异，不把计时器差异当成路径质量差异。

**统一后处理比较：** 将各前端动作重新交给同一连续完成器、相同车辆/profile、相同目标容差与审核，比较前端生成模式/几何的贡献。这张表用于解释学习是否真的改善候选和执行时间。

离线教师只用于训练集；测试任务不再查询教师作为网络输入。

### 12.2 必做消融

| 方法 | 验证问题 |
|---|---|
| 与 RL 相同掩码的均匀随机策略 | 改善是不是单靠掩码和解析连接获得 |
| 同动作库的距离贪心策略 | 网络是否学到超出手工局部引导的决策 |
| 仅行为克隆 | 强化学习微调是否有增益 |
| RL 不用全局引导 | 全局观测对长距离任务的作用 |
| RL 不用解析终端连接 | 末段成功有多少来自连接器 |
| RL 不作连续几何修复 | 后处理改变了多少成功率与路径时间 |
| RL 的掩码变为训练内碰撞惩罚 | 掩码对训练效率的作用；发布仍须最终审核 |
| RL 使用步数/长度代理奖励 | 使用真实终局计时校正的作用 |
| K=1/4/8 | 多候选代价与收益 |
| RL 核心模式 / RL+传统兜底 | 独立学习成功率与工程可靠性分开报告 |

核心 RL 可以包含预先声明的解析连接器，但不能调用完整传统搜索。若使用学习引导 beam/RRT，应新增一行方法，不混入核心策略数字。

### 12.3 指标与证据

优先记录发布轨迹安全、到达误差、成功率；然后记录完整规划 p50/p95、执行时间、平移/Spin/重配置分解、模式切换数、路径长度、倒车和低速区间、最小车体净空、兜底比例、连续化失败率、动作掩码耗时。

学习训练至少比较 3 个独立随机种子，论文定稿建议 5 个。用配对任务比较执行时间和计算耗时，同时报告双方成功的任务数与全部失败原因，避免只展示 RL 成功的容易任务。置信区间按布局与训练种子分组重采样；同地图的增广任务不能都视为独立地图样本。

每次正式评估按现有 [evaluation/TEMPLATE.md](../../evaluation/TEMPLATE.md) 生成可读报告，并给出：

- 每张地图四方法路径叠加图，A/O/Spin 用共同颜色。
- 速度与时间曲线；明确标出静止重配置段，Spin 另外着色。
- 完整规划时间分布、成功率和执行时间配对图。
- 多种子训练曲线、失败案例图和兜底占比。

训练日志、权重、轨迹和图片原件遵循 [evaluation/README.md](../../evaluation/README.md)，放仓库外归档。仓库保存文档、配置、代码、精简评估及模型清单/哈希；大权重不进入普通 Git 历史。

## 13. 风险、边界与停止条件

| 风险 | 如何识别 | 处理方式 |
|---|---|---|
| 动作库本身不能表达任务 | 同库有界搜索也不能重编码教师轨迹 | 调整分辨率或连接器，先于继续训练 |
| 策略只会 A 或频繁 Spin | 必要模式任务分组成功率、真实执行时间、模式分布 | 平衡任务分布与真实时间奖励，不禁止某种模式 |
| 掩码把推理速度优势吃掉 | 完整计时中 mask/sweep 占比最高 | 先验证向量化和保守几何界，再优化并行 |
| 原始动作可行，连续化后碰撞 | finalization_failure 分类 | 更严格的候选筛选、边界拟合与多候选，失败不发布 |
| 奖励偏好绕圈或过早失败 | 回报高但成功率/执行时间变差 | 检查终止势、失败惩罚、时间校正、循环分布 |
| 只有旧地图成绩好 | 布局隔离测试下降明显 | 扩展生成布局，冻结测试集，不反复调到记住预设点 |
| 兜底承担全部成功 | native_success、fallback_success 分开后差距大 | 不认定 RL 达到验收，回到观测或任务难度 |
| 看起来停顿不同 | 真正静止姿态区间、Spin 和低速区间混在一起 | 用发布轨迹的 x/y/yaw 与事件相位分开测量 |
| 系统环境升级破坏 ROS | ROS Python 依赖与 ML 依赖冲突 | 独立解释器与工作进程，锁版本 |
| 训练成本超预算 | 吞吐和成功率曲线长期无改善 | 先排查环境与可达性，再选择有界学习搜索，不无限堆训练 |

局部掩码加最终审核提供当前模型、地图与检查精度下的工程约束，不能宣称真实车辆绝对安全、概率完备或全局最优。

本方案的研究假设是：在现有可靠几何与计时底座上，学习提议能减少重复结构搜索，并找到不浪费切换时间的路径。假设必须由隔离测试证明；未达指标时报告未达标，不改换统计口径来宣布成功。
