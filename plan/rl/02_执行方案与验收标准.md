## 1. 最小交付目标

实现一个能在现有静态地图上生成完整 A/O/Spin 路径的学习规划器：

1. 策略同时选择运动模式与几何运动段。
2. 最终轨迹使用公共车辆模型、切换时间、连续重定时和整车审核。
3. 不依赖先完成一条传统完整路径，才能开始 RL 推理。
4. 对现有 11 张地图预设任务给出逐图结果；在按布局隔离的测试集上评估泛化。
5. 比较完整规划耗时与最终执行时长，区分核心 RL、解析连接、连续修复和完整传统兜底。
6. 产出路径图、时间曲线和可追溯原始数据，按现有 evaluation 模板写评估。

第一版训练 MaskablePPO 在有限原语库中选择动作；连续参数强化学习属于后续升级，不阻塞第一版交付。

## 4. P0：先冻结评价与计时合同

### 4.1 需要落实的参数

- 车体中心坐标、尺寸、轮距、轴距、最小转弯半径从公共车辆配置读取。
- A=0、O=1、Spin=2；amount/control 的单位和正负遵循现有 Action。
- 主实验沿用当前默认 mode_switch_only、target_v=2m/s；restricted 单独成组。
- 初始模式为 A；末尾可以是 Spin。起点即终点的零运动任务单独定义为成功，无需伪造切换。
- 最多一次平移方向反转，反转需要真实净 Spin；除非双方均显式启用 allow_shunting 对照。
- 连续发布验收先沿用 v2 显式采用的 0.02m 位置、1° 航向容差，而非搜索粗容差 0.16m/0.14rad。所有前端比较要显式传递，避免依赖构造器的宽松默认值。
- 最终整车扫掠精度、裕度、动态审核均沿用冻结 v2 合同，不能为了 RL 成功率放宽。

方向与不揉库约束要同时传给环境、终端连接器、完成器、最终审核，避免掩码允许而最终审核拒绝。

### 4.2 先实测当前停顿差异

用户已经观察到三个分支的切换停顿观感不同。P0 不以“代码常数相同”替代实际验证，须保存定时轨迹并分别测量：

| 时间组成 | 识别方式 |
|---|---|
| 真正模式重配置驻留 | event 相位内 x/y/yaw 均保持不变，持续时间由时间戳得出 |
| Spin 运动 | x/y 近乎不变而 yaw 改变，不能因中心 v=0 算驻留 |
| 切换前减速、后加速 | 位置随时间变化，但速度较低 |
| 同模式原语边界的零速 | 观察各原语端点及相邻相位，判断是否被错误当成模式切换 |

使用 A→O→A、A→Spin→A，以及连续 A 曲率变化三类确定输入。普通 profile 下每次模式驻留的定时事件应为 0.3s，数值容差先取 1e-6s；播放画面采样约 40ms，画面观察与轨迹时间戳精度分别记录。restricted 按公共函数计算的事件时间验证，不能强制把其物理转向延长剪成 0.3s。

四方法的统一后处理比较必须在这项计时合同核对后进行。原生 v1 的逐原语起停、v2 的连续段计时、legacy 的分组采样差异仍作为原生结果记录。

## 5. P1：公共完成器与无需 ROS 的训练环境

### 5.1 公共完成器

先从现有 v2 管线抽取最小函数，避免让 RL 调用 ModePathMaster.solve 再变成 v2 完整搜索：

~~~python
# P1 已实现；原 v2 在线调度尚未切换到这两个独立入口
finalize_candidate(problem, actions, config, deadline) -> FinalizationResult
finalize_candidate_set(problem, candidates, config, deadline) -> SelectionResult
~~~

FinalizationResult 包含原动作、连续计划、最终 timed samples、到达/整车/动态/方向检查、执行时间分解、拟合/修复过程与失败阶段。

流水线：

1. 检查参数有限、模式合法、动作量、方向历史与起终点输入。
2. 精确动作重放和完整原语扫掠。
3. 合并同模式同方向段，构造 ContinuousPlan。
4. 模式边界与终点拟合；必要时作有预算的固定结构几何修复。
5. retime_continuous，使用公共 MotionLimits、切换事件和段缓存。
6. evaluate_continuous_geometry，显式传入共同方向及终点合同。
7. 再核对实际发布 samples 的时间单调性、终点和插值扫掠。
8. 返回通过证书或失败原因；只有通过者能被最终选择和发布。

原语几何、拟合几何、最终发布几何分别保留哈希和审计状态。原语成功后连续化失败，记录为 continuous_projection/collision 等阶段，不修改其奖励为成功。

固定结构优化不得凭空改变模式后继续使用原模式掩码证据；若后续引入模式修改，应把它列为另一提议来源，重新走完整审核。

### 5.2 环境接口

~~~python
# 拟定 Gymnasium 接口
reset(seed=None, options=None) -> observation, info
action_masks() -> bool[80]
step(action_id) -> observation, reward, terminated, truncated, info
~~~

环境拥有完整路径历史，观测由独立 observation 模块生成。初始姿态必须先通过 pose_clear，因为 action_clear 的主要职责是检查后续运动段。

对非法编号、被掩码动作、全掩码状态、NaN、越界、耗尽动作步数，返回明确状态与原因，不尝试索引绕回。任务定义中的最大步数耗尽视为真正任务失败；如果是外部采样器中断，则是 truncated，并正确处理 bootstrap。剩余任务预算进入观测。[Gymnasium 官方说明](https://gymnasium.farama.org/tutorials/gymnasium_basics/handling_time_limits/)

### 5.3 本阶段需要的验证

| 用例 | 要证明的性质 |
|---|---|
| A/O/Spin 单步与组合 | 环境转移与 core.advance/replay 一致 |
| 矩形 Spin 只在中间角碰障碍 | 掩码不能只看首尾姿态 |
| A 转角可直接通过 | 不因模式规则强制插入 Spin |
| O 唯一可穿过的横向任务 | 动作库不是只会 A 的伪多模式 |
| 初始 O/Spin 运动段 | 起始 A 的切换计时只发生一次 |
| 连续 A 控制节点 | 决策次数不变成额外停车次数 |
| 反转/真实 Spin/相反 Spin 相抵 | 共同不揉库判断一致 |
| 地图比例与旋转裁剪 | 仅观测重采样，验碰用原物理地图 |
| 全无效掩码 | 失败可解释，不产生 NaN 策略 |
| 终局奖励逐项核算 | 累计成功奖励对齐最终 T_exec |

对掩码允许的动作，用独立更细扫掠抽检；优化版掩码必须与正确性参照对照。局部安全检查和最终审核共享基础车体模型，仍需承认共同模型错误的风险。

P1 出口先用随机策略与距离贪心跑通环境；这时还不宣布有学习规划性能。

| 首轮试验 | 200,000 transitions |
| 正式候选预算 | 每种子 2M 起；有改善才扩大到 10M |
| 训练种子 | 小试 1，正式至少 3，定稿建议 5 |

终局 T_exec 奖励、势函数、失败代价使用调研报告第 8 节公式。熵系数和 BC 辅助权重在后期降低，模型选择按实际成功与执行时间，不按训练回报最高。回报不等于最后的论文指标。

BC 先按验证掩码交叉熵与实际 rollout 成功率早停；随后环境交互微调。若继续保留 BC 辅助项，需要记录权重并与“仅 BC”比较。

Masked PPO 官方不支持循环策略。第一版使用显式历史特征；不能把 RecurrentPPO 和 MaskablePPO 的名称拼起来当作现成实现。并行环境的掩码放在环境内部，训练和评估均使用支持掩码的接口。[官方实现约束](https://sb3-contrib.readthedocs.io/en/master/modules/ppo_mask.html)

### 7.3 每次小试必须输出什么

- 实际 environment steps/s，掩码、终局完成器、优化更新、验证耗时占比。
- 成功率与分模式必要任务成功率。
- 实际 T_exec 与时间代理误差分布。
- 模式分布、反转次数、Spin 时间、0.3s 事件数量。
- 连续化失败、掩码耗尽、超步数、终点失败、审核失败分类。
- 原始回报分项与验证指标曲线。

算力预算按实测确定。例如 2M transitions 在 50/200/1000 steps/s 时，纯采样约需 11.1/2.8/0.56 小时；这只是算式示例，不含教师、训练更新、终局完成器与验证，也不是本机实测吞吐。不要给出未测量的“训练一晚必定完成”承诺。

### 7.4 中途停止与排障

若 200k 小试连基本开放区任务也不能完成，暂停扩大训练，按以下顺序检查：动作与坐标 → 掩码 → 目标判定 → 奖励符号与终局势 → 教师对齐 → 原语可达性 → 网络/优化。

基础任务改善但长距离失败时，再检查全局引导、历史特征和任务分布。未通过可达性检查时不无限增加 PPO 步数。

## 8. P4：有界多候选和推理速度

先做 K=1 确定性 rollout，随后增加固定种子的 K=4/8 有界采样。不同候选共享静态地图编码和可复用模板，路径/模式/控制签名去重。不同请求的动态历史与安全证书不互相混用。

靠近目标时尝试有预算的解析终端连接；可复用当前 A/O/Spin 的几何连接与拟合工具。普通 Reeds–Shepp 只描述相应车辆模型，不能直接冒充完整 4WIS 多模式连接器。

核心 RL 模式中，解析连接器只能负责约定局部末段，不调用全地图传统搜索。每次使用记录接入位置、连接长度、模式和时间，单列去除连接器的消融。

性能优化以剖析结果为准，顺序建议：

1. 静态地图张量/距离场只计算一次。
2. 共同规则先筛动作；运动模板与障碍索引复用。
3. 证明安全的简单距离界直接放行，其余完整扫掠。
4. 对批量候选做网络推理和 NumPy 操作批处理。
5. SegmentTimingCache 只复用局部时间求解，最终世界轨迹逐次审核。

必须同时报告网络 forward 的耗时和完整规划耗时。优化掩码不能通过加粗地图或省略 Spin 中间姿态制造速度提升。

## 9. P5：真正接入独立 RL 后端

### 9.1 入口调整

正式实现后，rl-mode-path 的 run_demo.sh 只接受本分支 rl_mode_path 后端。demo.launch 根据该后端启动 fwis_v3_rl_planner，直接消费 /map、起点和目标；不默认启动完整 C++ 搜索再等待 /plan/seed。

优化节点新增候选集回调，调用 candidate_finalizer。既有 /plan/timed_trajectory、/plan/path、/plan/quality_report、车体/模式/走廊显示继续使用共同发布逻辑。

ROS 桥接只做消息、参数、取消与身份管理。训练和推理核心不依赖 rospy。

### 9.2 拟定候选集消息

现有 PlanSeedCandidates 只含一个 proposal_primitives。多候选阶段新增独立消息：

~~~text
ModeCandidate.msg（拟定）
  uint32 candidate_id
  ModePrimitive[] primitives
  string source
  float64 policy_log_probability

PlanCandidateSet.msg（拟定）
  Header header
  uint32 plan_id
  Pose2D start_center
  Pose2D goal_center
  uint8 initial_mode
  string map_sha256
  string vehicle_profile_sha256
  string model_sha256
  ModeCandidate[] candidates
~~~

policy_log_probability 仅为诊断，不充当执行时间评分。source 至少区分 rl_rollout、rl_plus_analytic_connector、classical_fallback。模型来源与候选来源一起写入报告。

K=1 的早期原型可复用 PlanSeed，但不能让遗留 C++ 与 RL 同时向同一个主 seed 话题争抢发布。P5 完成多候选接口后固定发布关系。

### 9.3 独立推理工作进程

ROS Python 3.8 节点启动或连接常驻 Python 3.12 工作进程，通过 Unix socket 发送任务。初次请求加载地图、模型和动作库，后续按哈希复用。

每次回复必须回传 plan_id/map/profile/model/action_library 身份及原始候选。过期回复丢弃；新地图到来使旧缓存失效。取消和 deadline 应覆盖 rollout、连接和最终化，防止网络结束了但后处理无限继续。

模型 manifest 至少包含：

~~~yaml
# 拟定字段；不是当前已有的模型文件
model_id: <versioned_id>
weights_uri: <artifact_location>
weights_sha256: <sha256>
training_commit: <commit>
dataset_manifest_sha256: <sha256>
action_library_sha256: <sha256>
observation_schema_version: <version>
vehicle_profile_sha256: <sha256>
normalization_sha256: <sha256>
training_seed: <integer>
supported_direction_policy: <policy>
supported_initial_modes: [ACKERMANN]
validation_report: <path_or_uri>
~~~

模型缺失、schema 不匹配、连接失败、全掩码、终局审核失败要给出具体状态。RL 尚无合格候选时不把父版本成功结果改写成 RL 成功。

### 9.4 兜底边界

首个 RL 后端以核心模式完成验收，完整传统兜底默认关闭。若后续启用，在 RL 预算失败后显式请求传统流水线，累加全部 wall time，报告 fallback_used、fallback_source 和 native_success。

完整传统兜底是工程增强，不能成为“第四版已独立学会规划”的证据。不能为了让示例看起来总成功而预先并行运行传统规划、最后只展示最快网络时间。

### 9.5 ROS 验证范围

至少覆盖地图默认比例、预设起终点、RViz 手动改目标、方向策略、模型缺失、目标取消、旧结果晚到、worker 崩溃和超时。检查只有当前请求通过审核的轨迹被发布。

对比定时轨迹事件和 RViz 标记：默认模式事件包含真正 0.3s 静止采样，Spin 单独显示转动过程。同模式普通控制节点没有人为加的 0.3s。首版只接受显式静止 A 模式起点；其他初始模式返回 unsupported_initial_mode。后续若支持从实际 O/Spin 状态重新规划，需同步扩展当前把初始模式写为 A 的 retime_continuous 与审核、请求字段及训练分布，不能重置成 A 后漏计切换。

本阶段仍是 RViz 轨迹回放接入；真实底盘执行需要另行实现跟踪/驱动与执行时间同步，不能把 marker 在动当成硬件验证。

## 10. P6：四版本实验与图件

### 10.1 第一批工程对比

11 张地图预设任务 × 4 方法，每个固定输入至少重复 5 次热态运行，冷启动另外测。训练中的 3/5 个种子产生不同模型，推理重复不能替代训练种子。

记录原生流水线结果，并在可用原始动作的条件下增加统一完成器结果。基线不在测试任务上自动增加预算后只让 RL 保持小预算；共同预算和各原生预算分别标注。

### 10.2 正式泛化与消融

固定 500 任务主测试，按布局家族列成功率、端到端规划 p50/p95 与执行时间配对结果。核心 RL 关闭完整传统兜底。

首轮必做消融：同掩码随机策略、距离贪心、仅 BC、无终局真实计时校正、无解析连接、K=1/4，以及无几何修复。可先在固定 200 任务与 3 个训练种子上做，若发现关键退化再扩到主集。无掩码训练、无全局引导及连续参数方案在第二轮开展，不在第一轮无限扩大实验矩阵。

执行时间主比较使用双方成功的配对任务，并同时展示全任务成功覆盖。失败、超时按失败记录；规划 wall time 应包括到达失败预算的运行，分布图明确删失/超时处理，不能只画成功样本的快请求。

### 10.3 每次测试必须交付的材料

按 [evaluation/TEMPLATE.md](../../evaluation/TEMPLATE.md) 填写短报告，再增加以下 RL 字段：

| 类型 | 最少字段 |
|---|---|
| 身份 | 分支/commit、模型/数据/动作库哈希、训练种子、方向/profile、地图比例 |
| 成功 | native_success、final_success、到达误差、扫掠/动态审核、失败阶段 |
| 时间 | 冷/热完整 wall、map/guide/mask/network/connector/finalize 分解 |
| 执行 | T_exec、T_translation、T_spin、T_switch_hold、每次事件持续时间 |
| 贡献 | 解析连接比例、连续修复比例、传统兜底比例、后处理前后时间 |
| 路径 | 路径长、净空、模式序列、倒车、反转与低速区间 |
| 训练 | transitions、吞吐、总训练耗时、教师生成耗时、验证选择规则 |

至少生成四类能直接阅读的图片：

1. 每张地图四方法轨迹图，标明起终点、模式和碰撞/失败位置。
2. 速度—时间与 yaw—时间图，模式驻留区间着色，Spin 转动另标。
3. 完整规划耗时和执行时间配对图，显示样本数及失败覆盖。
4. 多训练种子学习曲线和典型失败案例。

原始证据与图片放外部归档，报告链接精确 run_id；仓库的 evaluation/rl 中保存精简结论、必要缩略图或稳定图片索引。遵守现有归档流程，不再次产生无图、只有抽象文字的性能报告。

## 12. 验收标准

下面是拟定目标，P0 记录基线后冻结；需要调整时必须在正式测试前说明理由和版本，不根据测试结果事后降低标准。

### 12.1 必须通过的功能与正确性门槛

- 确实由学习策略生成模式与几何动作序列，核心模式不预先调用完整传统规划。
- 发布轨迹的整车扫掠、终点、动态和方向审核全部通过；发现一条审核失败仍发布的轨迹即不通过。
- 最终位置误差不超过共同 0.02m、航向误差不超过 1°；记录共同配置及任何特殊任务要求。
- 80 动作库与单步重放一致，Spin 中间角碰撞被拦截，真实反转历史可核对。
- 默认 profile 的每个重配置事件按公共 0.3s 时间戳验证；不以 v=0 自动判定静止。
- 在同模式连续控制节点不因 RL 决策次数增加模式驻留；首模式非 A 时初始切换被计入。
- 数据、模型、任务和 source 可追溯；异常和超时有明确失败阶段。
- run_demo 在 RL 实现后只绑定 rl_mode_path，模型缺失不静默回退冒充 RL。

### 12.2 核心 RL 的效果门槛

| 项目 | 拟定要求 |
|---|---|
| 可复现性 | 至少 3 个训练种子；固定任务、配置、模型与硬件身份 |
| 主测试成功率 | 相对冻结 v2 不劣于 2 个百分点；报告配对差及按布局/种子重采样的 95% 区间 |
| 实质速度目标 | 完整热态规划耗时配对中位数至少降低 20%；同时置信区间应支持确有改善 |
| 尾部耗时 | p95 不显著恶化，拟定比值不超过 1.05，并展示超时比例 |
| 执行时间 | 共同后处理下配对中位比值不超过 1.02；较大退化任务单独列出，不能用规划更快遮盖 |
| 泛化 | 分开报告未见布局与未见拓扑，不把训练地图增广算成未见地图 |
| 11 地图工程回归 | 报告全部预设任务，已有基线可行任务中的 RL 失败必须逐例说明 |
| 贡献可见 | 优于同掩码随机/贪心，且报告 BC、连接器与后处理的贡献 |

成功率非劣性若证据不足，结论写“尚不能确认”，不只凭点估计宣布通过。若速度目标未达而执行时间明显改善，可作为另一项研究结果报告，但不能宣布“搜索加速验收通过”。

完整传统兜底的成功不计入核心 RL 成功率。工程增强模式可以另外验收可靠性，其耗时必须包含 RL 失败尝试与兜底。
