# 迁移顺序与风险

`continuous-mode-path@956bc64` 作为 ROS2 分支基线。它的公共头文件和地图工具与另外三个分支一致，单车消息定义相同，可用多车分支提供额外的八种消息。工作在单独的 `ros2_ws`，四个 ROS1 提交原样保留。

1. 在 ROS Humble 上校验 Harmonic、桥接和 RViz2。Humble 的默认 Fortress 包与 OSRF 对应 Harmonic 包冲突，安装事务须先检查。
2. 共享 Ranger URDF 中的模型几何与官方网格。接收 Gazebo 根位姿，在仿真时间下发布独立 TF。
3. 迁移消息生成和公共头文件，将地图适配保留在 OccupancyGrid 输入处。
4. 依矩阵顺序移植单车节点和回放，用四个源提交分别保留算法版本和默认参数。多车用指定分支默认规划流水线和独立的编队输入。
5. 统一后端选择、ROS2 参数与 RViz2。使用可重放的平直无障碍场景校验消息、路径、时间与编队几何；ROS1 smoke 和复杂场景回归依赖 Noetic 环境。

主要风险为 ROS1 latch 对应的 ROS2 QoS、时间消息纳秒字段、场景的 `map` 原点、Python ROS2 消息类型严格性、CasADi 求解器插件版本和多车回放握手。优先在适配边界处理，原算法及参数权重保持来源语义。
