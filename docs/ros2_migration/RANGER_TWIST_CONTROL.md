# Ranger Mini 2.0 车体 Twist 控制接口

上层控制器按车发布车体速度 `Twist`。底盘驱动根据分量选择前后 Ackermann、Spin 或 Parallel，并负责舵轮和驱动轮控制。规划器内部应保留期望模式，**Ackermann 段必须限制最终下发的偏航角速度，防止减速或跟踪修正触发被动切换到 Spin**。

单车跟踪器在 0.810 m 的机械半径参照上加裕量，当前工作半径为 0.830 m。实现、参数和试验结果见 [单车多模式 Twist 跟踪实施与验收](RANGER_TWIST_TRACKING_REPORT.md)。

## 1. 消息和话题

记 `Twist = (vx, vy, wz)`。三个分量都在本车 `base_link` 坐标系下定义。其余分量置零。

| 字段 | 含义 | 单位和正方向 |
|---|---|---|
| `linear.x = vx` | 纵向线速度 | m/s，向前为正 |
| `linear.y = vy` | 横向线速度 | m/s，向左为正 |
| `angular.z = wz` | 车体偏航角速度 | rad/s，俯视逆时针为正 |

如果控制器内部用曲率、转角或目标航向，先转换为车体偏航角速度再填 `angular.z`。旧脚本里的变量名 `steer_opt` 不能作为这个字段的单位约定。消息定义和坐标约定见 [ROS 2 Humble Twist](https://github.com/ros2/common_interfaces/blob/humble/geometry_msgs/msg/Twist.msg) 和 [REP 103](https://github.com/ros-infrastructure/rep/blob/master/rep-0103.rst)。

| 接入环境 | 指令话题和消息类型 |
|---|---|
| 历史 ROS 1 三车脚本 | `/robot1/four_wheel_steering_controller/cmd_vel`、`/robot2/four_wheel_steering_controller/cmd_vel`、`/robot3/four_wheel_steering_controller/cmd_vel`，`geometry_msgs/Twist` |
| 2026-11-19 单车采集 | Ranger 原生驱动订阅 `/cmd_vel`，`geometry_msgs/Twist` |
| 本工程 ROS 2 仿真 | 启用 `motion_test:=true` 后，`/ranger_sim/cmd_vel` 接收 `geometry_msgs/msg/Twist`，同一条指令发给三辆仿真车 |
| ROS 2 实车接入 | AgileX 参考驱动默认订阅绝对话题 `/cmd_vel`，`geometry_msgs/msg/Twist`。多车部署时为每台驱动显式重映射到独立话题，并核对实际订阅关系 |

## 2. 三种模式的编码和运动学

理想运动学以 `(x, y, ψ)` 表示车体参考点在世界系的位姿。三个模式共用以下变换，模式约束作用于车体系输入。

```text
ẋ = vx cos(ψ) − vy sin(ψ)
ẏ = vx sin(ψ) + vy cos(ψ)
ψ̇ = wz
```

| 期望模式 | 发出的 `(vx, vy, wz)` | 车体运动 | 示例 |
|---|---|---|---|
| 前后 Ackermann | `(vx, 0, wz)`，转弯时满足第 3 节约束 | 仅沿车头方向平移并改变偏航。直行属于此模式，`wz = 0` | 直行 `(0.10, 0, 0)`，左转 `(0.10, 0, 0.15)` |
| Spin | `(0, 0, wz)`，使用已验证可响应的非零偏航指令 | 车体参考点原地旋转 | `(0, 0, 0.15)` |
| Parallel | `(vx, vy, 0)`，`vy ≠ 0` | 航向固定，车体沿平面速度向量平移。`vx = 0` 为纯横移，`vx ≠ 0` 为斜移 | 左横移 `(0, 0.10, 0)`，斜移 `(0.10, 0.05, 0)` |

Mini 2.0 的参考驱动先判断 `vy != 0`，命中即进入 Parallel，该支路忽略 `wz`。因此 Ackermann 和 Spin 必须把 `vy` 明确写成零，Parallel 必须把 `wz` 明确写成零。11 月 19 日 C 组在 `(vx, vy) = (0.10, 0.05)` 时分别请求 `wz = 0、+0.10、−0.10 rad/s`，三次均下发模式 1，运动帧完全相同。速度向量的方向由 `vx`、`vy` 决定，纯横移直接发 `vx = 0`。斜移及横移允许的方向、速度幅值和倒车响应以部署版本的实测结果为准。 [AgileX 参考驱动](https://github.com/agilexrobotics/ranger_ros2/blob/b6ea21a275ca5e7168130cc6470e61474681d679/ranger_base/src/ranger_messenger.cpp#L391)

Spin 和 Parallel 还需采用各自已验证的速度上限、加减速和起步条件。上表是车体运动学模型。底盘反馈和车体实际运动会受到模式切换、限幅及接地条件影响。

## 3. Ackermann 到 Spin 的边界

当 `vy = 0` 且 `wz` 非零时，驱动使用指令半径 `R_cmd = |vx| / |wz|` 选模式。参考 ROS 2 驱动将 `|wz| < 1e-6 rad/s` 视为直行。对转弯输入，源码条件为 `R_cmd < R_switch` 时选择 Spin，等于阈值时仍走 Ackermann 分支。进入 Spin 后，驱动把纵向速度指令设为零，按 Spin 分支发送偏航角速度。这会让轨迹从有平移的圆弧骤变为原地旋转。

| 依据 | 切换半径 |
|---|---:|
| 2026-11-19 ROS 1 实车工控机交接记录 | `0.47644 m` |
| 本工程 ROS 2 Gazebo 测试节点 | `0.47644 m` |
| AgileX ROS 2 参考代码的 `RangerMiniV2Params` | `0.4764 m` |

控制器参数应跟随每台车实际部署的驱动版本。实车 B1 测试验证了阈值两侧的模式行为。表中的半径由发送值计算，车体真实轨迹半径需独立测量。 [工控机环境与离线开发交接](../../../real_data/ranger_interface%2811.19%29/工控机环境与离线开发交接.md) · [AgileX 车型参数](https://github.com/agilexrobotics/ranger_ros2/blob/b6ea21a275ca5e7168130cc6470e61474681d679/ranger_base/include/ranger_base/ranger_params.hpp#L48) · [仿真模式判定](../../ros2_ws/src/ranger_mini_gz/scripts/twist_motion_test#L18)

| B1 发出的 `vx`（m/s） | `wz`（rad/s） | `R_cmd`（m） | CAN 模式请求与稳态反馈 |
|---:|---:|---:|---|
| 0.10 | 0.111111 | 0.90 | 模式 0，Ackermann |
| 0.10 | 0.153846 | 0.65 | 模式 0，Ackermann |
| 0.10 | 0.200000 | 0.50 | 模式 0，Ackermann |
| 0.10 | 0.250000 | 0.40 | 模式 2，Spin。下发纵向速度 0、Spin 角速度 0.25 rad/s |

B2 近零速度用例 `(0.005, 0, 0.10)` 同样进入 Spin。0.80 m 工况的内外车请求分别为 `(0.020, 0, 0.10)` 和 `(0.140, 0, 0.10)`。按 0.7 同比例降速后，两者的指令半径仍分别为 0.20 m 与 1.40 m，轮流上车回放时仍分别是 Spin 和 Ackermann。**死区应按每辆车实际发出的 Twist 计算，编队名义半径和整体降速都无法代替逐车检查。** [11 月 19 日实车归档与运行索引](../../../real_data/ranger_interface%2811.19%29/README.md)

## 4. 控制器的死区与限幅

取 `R_guard = R_switch + ΔR`，其中 `ΔR > 0` 覆盖跟踪修正、离散化、指令量化及版本差异。对仍在 Ackermann 的段，驱动阈值以内以及阈值到 `R_guard` 之间均禁止下发转弯指令。令规划器与发布端都检查以下约束，可避免低速除零。

```text
vy = 0
R_guard × |wz| ≤ |vx|
```

- **规划和 MPC。** 每个预测步都满足约束。给定前进或倒车方向 `s = +1` 或 `−1` 时，可写成 `s·vx ≥ 0` 和 `−s·vx/R_guard ≤ wz ≤ s·vx/R_guard`。用曲率参数化时，取 `wz = vx·κ` 与 `|κ| ≤ 1/R_guard`。
- **发布前最后一道约束。** 在跟踪补偿、插值、滤波及速度限幅之后，用最终的 `vx_cmd` 算 `wz_max = min(wz_limit_ack, |vx_cmd|/R_guard)`，再把 `wz_cmd` 限制在 `[−wz_max, +wz_max]`。若通信层量化指令，检查量化后的值。检测到非有限值、超出约束或限幅导致跟踪不可接受时，将结果返回上层重算或进入已验证的停止流程。
- **减速、停车和反向。** Ackermann 段令 `wz` 随 `|vx|` 一起减小。接近零速时，按部署标定的门槛将 `wz` 归零，再按停车或反向状态执行。若同时约束角加速度和减速度，要联立求可行指令，避免减速比角速度下降更快而越界。低速下保留独立航向修正量会触发 Spin。
- **刚性编队。** 对每台车从编队参考点换算到各自车体系后，再检查最终输入及模式。若某车需要限幅，联合求解或重规划，使输出继续满足编队约束。单独裁剪某车的 `wz` 会改变它的曲率。

例如离线联调可先设 `R_guard = 0.55 m`。此时 `vx_cmd = 0.10 m/s` 对应的最大 `|wz_cmd|` 约为 `0.1818 rad/s`，可以发 `(0.10, 0, 0.18)`。原请求 `(0.10, 0, 0.25)` 在 Ackermann 段应限幅或重规划。0.55 m 是离线设计示例，最终裕量由各车部署版本和边界复测确定。

## 5. 主动切换与反馈确认

1. **由规划器显式提交目标模式。** 仅在规划要求旋转时发布 Spin 形态。仅在规划要求横移或斜移时发布 Parallel 形态。不得把 Ackermann 越界当成一个正常的模式迁移动作。
2. **过渡时继续满足当前模式的约束。** Ackermann → Spin 时按 Ackermann 包络降低纵向速度和角速度。满足项目确认的停止或过渡条件后，再发送 `(0, 0, wz)`。Spin → Ackermann 时结束自旋，确认转动衰减满足条件后，从直行或包络内的低速转弯进入。Parallel 切换同样由控制器显式选段并用对应字段编码。
3. **等待车端确认。** 从每车的模式反馈和车体运动反馈确认进入目标模式后，再推进轨迹段。旧实车记录中模式已经改变而切换标志仍为 0，应检查反馈模式字段本身及新鲜度。未确认、反馈过期、意外进入 Spin 时暂停轨迹推进，由车辆接入层执行现场已验证的停车或故障处理流程。

实车的切换与起动需要时间。E2 复测从近零舵角发令到持续轮端起转，纯横移约 0.631–0.669 s，自旋约 0.633–0.813 s。D2 的特定低速直行切斜移观察到轮端连续转动。这些记录可用于离线时序估计，通用过渡条件仍须结合反馈标定。 [实车复测记录](../../../real_data/ranger_interface%2811.19%29/工控机环境与离线开发交接.md)

仿真节点接收全零 Twist 或 0.35 s 未收到新指令后停止更新位姿。2026-11-19 的 ROS 1 工控机交接记录提示旧驱动的全零输入可能遇到 `0/0`，现场试验使用原生驻车与独立急停。实车部署应由车辆接入层核实停车与超时行为。上层算法接口仍只下发车体 Twist。

## 6. 离线验证

按 [ROS 2 工作空间说明](../../ros2_ws/README.md#三车-twist-基础测试) 启动隔离仿真。该说明里的 `(0.10, 0, 0.20)` 用来检查驱动近边界行为，控制器启用示例死区后应按第 4 节改用包络内的指令。

| 用例 | 预期 |
|---|---|
| `(0.10, 0, 0.15)` 与 `(−0.10, 0, 0.15)` | Ackermann，前进和倒车都满足半径约束 |
| Ackermann 请求 `(0.10, 0, 0.25)` | 发布端限幅或重规划。旁路保护直发给仿真时，应观察到 Spin |
| Ackermann 减速到零及反向 | 每个最终下发点均满足包络，低速归零时没有残余偏航触发 Spin |
| 主动切换 Spin、Parallel | Spin 仅偏航，Parallel 仅平移，模式由目标段决定 |
| 编队内外车回放 | 分别记录每车的请求、最终指令、期望模式和反馈模式，确认所有 Ackermann 段均未被重写成 Spin |

本页依据 ROS 1 单车记录、固定提交的 ROS 2 参考源码及现有 Gazebo 测试节点编写。第 4 节给出后续控制器的设计约束与验收条件，实车控制器的死区标定和编队联调待执行。
