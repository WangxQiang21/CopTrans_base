## P0：碰撞数值误差包络按全宽传入，只生效一半

### 已确认的源码事实

- `formation_continuous_a/collision.py:error_envelope` 将 `maximum_envelope_m` 一次加到旧 checker 的 `margin_m`，并验证 `margin_used >= baseline + envelope`。
- 旧 `formation_collision.py:FormationCollisionChecker.__init__` 的单侧半长/半宽是 `(shape_dimension + margin_m)/2`。因此在不改旧 checker 的情况下，传入 margin 相比基准增加 `Δm`，每侧的实际增长只有 **`Δm/2`**，不是 `Δm`。旧 checker 的 sweep padding 以单侧 `padding` 生效，具有覆盖采样间运动的另一用途，不能无证据地同时作为全部数值误差包络。
- 数值包络 `e = eps_position + (|offset|+radius)*eps_psi + radius*eps_relative_heading` 是对车辆位置/角点的径向位移界。若通过 checker 的全尺寸 `margin_m` 覆盖每侧 `e`，至少应满足 `(margin_used-baseline_margin)/2 >= max(e_i)`，并对实际扩张半径与 margin 的耦合重新求保守上界。

以正式 S1 记录独立重算：`e=4.1494137344255645e-08 m`，`(margin_used-baseline)/2=2.0747068674165092e-08 m`，不足以覆盖所声明的包络；六个正式场景均同样不足。**这证明现有误差包络覆盖性论证不成立，不表示已证明场景实际发生碰撞。**
