## 1. 目标和架构选择

最终交付：现有项目启动→RViz 设置货物起终点和方向→自主规划统一 A/O/S 刚性编队轨迹→显示路径/设置位置→按共同时间同步回放三车完整运动。失败不得播放旧结果；首版单请求串行。范围止于规划回放，无控制器、Gazebo 或实车。

**采用 Python 模式感知搜索和权威内部运动序列。** S5/S8/S9、Spin、公共时间、配置和显示核心已有 Python 实现；旧 C++ 几何种子不保存模式/车头，新架构不再经它重建路径。保留 C++ 源码和旧入口作为基线，不改成大量兼容补丁。

| 方案 | 实际修改范围 | 重复逻辑/测试性 | 性能风险 |
|---|---|---|---|
| 扩展 C++ 搜索＋新权威种子 | C++ 状态/边/去重、模式碰撞、ROS 消息、Python 反序列化和审核 | 两端原语需一致，跨语言合同测试更多 | 有 C++ 既有搜索基础，但新高分支状态仍未测 |
| **Python 进程内（采用）** | 新搜索/统一边、S8/S9 适配、薄 ROS 入口和回放封装 | 直接复用已有 Python 几何/轮系/碰撞，离线可测；无种子往返 | Python 扩展/验碰可能慢，须在 FR03/04 计量，不能预言实时性能 |

证据是代码的语言与接口分布，不是未经实测的速度比较。优先采用小型有限原语库与明确预算，性能超限时先诊断，再由 Codex 决定实现层优化；不得自动改变研究模型。

**数学与实现：** motion 的 q_F/theta 用原边及五次进度；setup pose 固定、旧 mode 保持至结束后统一切换；起点初始 A/零曲率设置必须计时；同模式角差也计设置。精确边序列不重选模式/方向。规范模型序列化后可还原同一采样器，样本是投影。独立审核从几何导数重算 A/O/S、公共模式、曲率/方向/轮系及扫掠，不以同一构造器的布尔标志作证明。
